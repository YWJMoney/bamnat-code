# 밤낮 회사 규칙 서버 (bamnat-company)

같은 회사 사람들이 근무 설정과 급여 계산 방식을 나눠 쓰는 서버예요. 금액은 오가지 않아요.
개발자 앱은 같은 주소의 `/admin/`에 있어요 [COMM-04][COMM-01][COMM-02][COMM-03][ADMIN-01]. 앱 문의도 이 서버로 와요 [ADMIN-02].

Cloudflare 무료 요금제로 충분해요. 공유 링크 서버(`server/share-worker`)와는 따로 올려요.

## 배포하기 (Cloudflare 대시보드)

공유 링크 서버를 올린 같은 Cloudflare 계정에서 해요.

1. **D1 데이터베이스 만들기**
   왼쪽 메뉴 저장소 및 데이터베이스(Storage & databases) → D1 SQL 데이터베이스 → 데이터베이스 만들기(Create).
   이름은 `bamnat-company`로 해요. 표는 서버가 처음 쓸 때 스스로 만들어요.
2. **Worker 만들기**
   컴퓨팅(Workers) → Workers 및 Pages → 만들기(Create) → Worker → Hello World로 시작.
   이름을 `bamnat-company`로 하고 배포(Deploy)를 눌러요.
3. **코드 붙여 넣기**
   만든 Worker에서 코드 편집(Edit code)을 눌러요. `worker.js` 내용을 모두 지우고 출시용 `worker.js` 전체를 붙여 넣은 뒤 배포(Deploy)를 눌러요.
   출시용 `worker.js`는 이 폴더에서 `npm run bundle`로 만들어요(`dist/worker.js`). `src/index.js`와 개발자 앱 화면(`src/admin-app.js`)을 한 파일로 합친 거예요.
4. **데이터베이스 연결**
   Worker 화면의 바인딩(Bindings) → 바인딩 추가(Add binding) → D1 데이터베이스.
   변수 이름은 `DB`, 데이터베이스는 `bamnat-company`를 골라요.
5. **비밀값 두 개 넣기**
   `bamnat-company` Worker → 설정(Settings) → 런타임 변수(Runtime variables) → 변수 추가(Add variable).
   화면에 따라 변수 및 비밀(Variables and Secrets) → 추가(Add)로 보이기도 해요. 환경은 Production에 체크해 두고,
   줄마다 Secret에 체크해요. 두 번째 줄은 + Add로 만들어요.
   - `ADMIN_PASSWORD`: 개발자 앱 비밀번호예요. 10자 이상으로 직접 정해요.
   - `RATE_SALT`: 아무 긴 글자예요. 비밀번호 생성기로 만든 32자 정도면 돼요. 공유 링크 서버의 것과 달라도 돼요.

   Key는 대문자와 밑줄 그대로, 앞뒤 빈칸 없이 써요. 마지막에 파란 Add variable and deploy(배포)를 눌러야 서버가 읽어요.
   옆 화살표 메뉴의 저장만 하는 버튼은 배포가 되지 않아요.
   같은 설정 화면 아래쪽 빌드(Build)의 변수 칸이나 왼쪽 메뉴의 Secrets Store에 넣은 값은 서버가 읽지 못해요.
   서버가 비밀번호를 읽기 전에는 로그인 화면의 입력칸이 잠겨 있어요.
   두 값 모두 채팅이나 메신저로 보내지 마세요.
5-1. **매시간 정리 켜기** [ADMIN-02]
   `bamnat-company` Worker → 설정(Settings) → 트리거(Triggers) → 크론 트리거 추가(Add Cron Trigger)에서 `17 * * * *`(매시 17분)를 넣어요.
   아무도 보내지 않는 시간에도 네트워크 해시(2시간), 다 쓴 제한과 로그인, 180일 지난 문의, 1년 지난 기록이 제때 지워져요.
6. **확인**
   휴대폰 크롬 주소창에 `https://bamnat-company.<계정 이름>.workers.dev/admin/`을 그대로 입력해요. 검색으로는 나오지 않아요.
   `<계정 이름>`은 비밀값이 아니라 Cloudflare가 정한 workers.dev 이름이에요. 공유 링크 서버 주소(`bamnat-share.<계정 이름>.workers.dev`)의 가운데와 같고,
   Worker → 설정(Settings) → 도메인 및 경로(Domains & Routes)에도 전체 주소가 나와요. RATE_SALT는 주소에 넣지 않아요.
   빠진 설정이 있으면 로그인 화면 아래 "서버 준비"에 무엇을 하면 되는지 나와요.
   로그인한 뒤 크롬 메뉴(⋮) → 홈 화면에 추가를 누르면 앱처럼 열려요.
7. **주소 알려 주기**
   workers.dev 주소만 Claude에게 알려 주세요. 앱 연결은 Claude가 해요. 비밀번호와 RATE_SALT는 알려 주지 않아요.

5-2. **(정식 출시 전에만) Play 구매 확인 키** [MON-03]
   Play Console › 설정 › API 액세스(또는 Google Cloud)에서 서비스 계정을 만들고, Play Console › 사용자 및 권한에서 그 계정에 '재무 데이터 보기, 주문 및 구독 관리'를 줘요.
   받은 JSON 키 파일 내용을 통째로 5번과 같은 곳에 Secret `PLAY_SERVICE_ACCOUNT`로 넣어요. 채팅이나 메신저로 보내지 마세요.
   없으면 서버는 구매를 `verified:false`로 답하고(앱은 휴대폰의 Play 상태를 써요), 체험 전환 동의가 없을 때 다음 결제를 멈추지 못해요.
   패키지 이름이 `com.bamnat.app`이 아니면 일반 변수 `PLAY_PACKAGE`도 넣어요.

코드를 고친 뒤에는 3번만 다시 하면 돼요. 데이터베이스와 비밀값, 크론 트리거는 그대로 남아요.

## 개발자 앱 (/admin)

휴대폰, 펼친 폴드, 컴퓨터에서 같은 주소로 열려요. 폰은 아래 탭, 폴드와 태블릿은 왼쪽 레일, 컴퓨터는 사이드바로 바뀌고, 휴대폰 글자 크기를 키워도 줄이 넘치지 않게 따라 커져요.
크롬이나 삼성 인터넷에서 앱 설치(홈 화면에 추가)를 누르면 스토어 없이 앱으로 설치돼요. 설치 방법은 `/admin/install`에 있어요.

화면은 하는 일에 따라 여섯 허브로 묶여요(1.28 [ADMUX-30]). 허브 안의 화면은 제목 아래 탭으로 오가고, 컴퓨터 사이드바에서는 연 허브 아래에도 보여요. 폰 아래 탭은 오늘·문의·광장·출시와 더 보기(분석·관리), 폴드 레일과 사이드바는 여섯 개예요. 권한이 없는 허브와 탭은 아예 안 보이고, 탭이 하나뿐인 허브는 탭 줄이 없어요. 허브의 첫 탭 위에는 '지금 기다리는 것'이 있어 누르면 그 목록이 걸러진 채로 열려요. [ADMUX-31]

[ADMUX-37]~[ADMUX-39] 1.27의 `/api/admin/overview`·`/api/admin/inbox`는 1.29에서 지웠어요. 그때 열어 둔 탭이 부르면 410 `{error: "moved", to, build}`로 새 자리와 지금 판을 알려 주고, 새로 고치면 새 앱이 열려요. [ADMCP-07]

### 지표의 Play 통계와 원격 갱신 [ADMUX-15][ADMUX-16]

- **Play 비정상 종료·ANR**: 구매 확인에 쓰는 비밀값 `PLAY_SERVICE_ACCOUNT`의 서비스 계정을 그대로 써요. 새 비밀값은 없고 두 가지만 켜면 돼요.
  1. Google Cloud 콘솔 → 그 서비스 계정의 프로젝트 → API 및 서비스 → **Google Play Developer Reporting API** 사용.
  2. Play Console → 사용자 및 권한 → 그 서비스 계정 → 앱 권한에 **앱 정보 보기 및 대량 보고서 다운로드(읽기 전용)**.
  켜기 전에는 출시 관문 G0가 "Play 권한 필요"(계정은 있는데 Play가 거절) 또는 "Play Console에서 확인"(계정 없음)으로 보여요. 값은 Play 기준으로 하루이틀 늦게 들어오고, 서버는 6시간마다 한 번만 물어요.
- **원격 갱신**: 앱이 받는 공개 파일(`https://ywjmoney.github.io/-/remote/v1/`)을 서버가 읽어 서명이 실제로 맞는지 확인해요. 다른 주소를 쓰려면 선택 변수 `REMOTE_BASE_URL`을 넣어요(없어도 돼요). '다시 확인'을 누르면 10분 보관을 건너뛰고 바로 받아요.

### 관리자 앱 알림(웹 푸시) [ADMIN-19]

새 문의, 급한 문제 신고, 신고로 가려진 글, 새 관리자 가입을 관리자 휴대폰·컴퓨터에 알림으로 보내요. 서버에 비밀값 두 개가 있어야 켜져요(없으면 관리 › 내 계정·이 기기의 알림 카드에 "서버에 알림 키가 아직 없어요"라고 보여요).

1. 내 컴퓨터에서 `node tools/vapid-keys.mjs`를 실행하면 `VAPID_PUBLIC_KEY=…`, `VAPID_PRIVATE_KEY=…` 두 줄이 나와요.
2. Cloudflare 대시보드 → 이 Worker → Settings → Variables and Secrets에서 둘 다 **Secret**으로 넣어요. 선택으로 `VAPID_SUBJECT`(`mailto:내메일`)도 넣을 수 있어요. 깃에는 절대 올리지 않아요.
3. 개발자 앱 → 관리 › 내 계정·이 기기 → 이 기기 알림에서 "이 기기에서 켜기", 받을 종류와 조용한 시간을 고르고 "시험 보내기"로 확인해요. 기기마다 따로 켜요.

키를 바꾸면 모든 기기에서 다시 켜야 해요.

## 관리자 계정과 권한 [ADMIN-04]

- **최고 관리자**는 `ADMIN_PASSWORD`로 로그인하는 사람이에요(로그인 화면의 "최고 관리자" 탭). 모든 화면을 쓰고, 관리자를 초대·승인하는 건 최고 관리자만 해요.
- **관리자 계정**은 아무나 만들 수 없어요.
  1. 최고 관리자가 관리자 화면에서 메일과 권한을 정하고 초대 링크를 만들어요. 링크는 한 번만 보이고 7일 동안 열려요. 서버에는 해시로만 남아요.
  2. 그 링크를 그 메일로 보내요("메일로 보내기"는 메일 앱을 열어요). 링크는 그 메일 하나에만 쓰여요.
  3. 링크를 연 분이 이름과 비밀번호(10자 이상)를 정해 계정을 만들고, 앱을 설치해요. 계정은 "승인 대기"로 시작해요.
  4. 최고 관리자가 승인하면 그때부터 메일과 비밀번호로 로그인돼요.
- **권한**은 영역마다 없음·보기·고치기 중에서 골라요: 검토, 문의, 개발사항, 회사·규칙, 보상, 채택 설정, 토론(임금표 포함), 활동 기록(보기만).
  **광장 규칙 내리기**(채택된 규칙·채택된 시세를 내리거나 다시 올리기)는 없음·줌으로만 골라요. 최고 관리자와 운영 관리자 묶음만 처음부터 있어요. 보낸 분도 채택된 것을 지울 수 없어요 [PLZ-06]. 운영 관리자·검토 담당·문의 담당·보기 전용으로 한 번에 고를 수도 있어요.
  **개발사항 처리**(개발중·완료·반려 정하기, 여러 개 한 번에 처리)는 없음·줌으로만 골라요. 최고 관리자는 늘 있고, 다른 관리자는 최고 관리자가 줄 때까지 없어요 [ADMIN-10].
  개발사항이 생기기 전에 초대한 관리자는 모두 개발사항 고치기(넣기·고치기·지우기)로 시작해서, 권한을 다시 고르지 않아도 바로 써요. 처리는 따로 받아야 해요.
  권한을 바꾸거나 멈추거나 삭제하면 바로 적용돼요. 멈추거나 삭제한 계정은 그 자리에서 로그아웃돼요. 서버에 새로 생긴 경로는 권한을 정하기 전까지 최고 관리자만 써요.
- 비밀번호는 PBKDF2 해시로만 남아요. 한 계정에서 5번 틀리면 어느 네트워크에서든 1시간 잠겨요. 관리자는 내 계정에서 비밀번호를 바꾸고 모든 기기에서 로그아웃할 수 있어요.
- **메일 확인 코드(선택)**: Worker 비밀값에 `MAIL_API_KEY`(Resend의 API 키)와 `MAIL_FROM`(예: `밤낮 <no-reply@내도메인>`, Resend에서 확인한 도메인)을 넣으면,
  가입할 때 초대받은 메일로 6자리 코드가 가고 코드를 넣어야 계정이 만들어져요. `OWNER_EMAIL`을 넣으면 누가 가입했을 때 최고 관리자에게 알림 메일이 가요.
  넣지 않으면 서버는 메일을 보내지 않고, 초대 링크를 메일로 보내는 것이 메일 확인이에요.
- 이 버전으로 바꾸면 예전 로그인은 한 번 끝나요. 최고 관리자 탭에서 다시 로그인하면 돼요.

## 채택되는 방식

- 같은 회사, 같은 부서, 같은 규칙을 서로 다른 3명 이상(광장 › 채택 규칙에서 2~10명, 결정 D32)이 보내 점수가 채택 점수에 닿으면 자동으로 채택돼요.
- 근무 시간과 순서, 연장·휴무일 근무 방식, 가산율, 감시·단속 승인과 휴게 같은 회사 규칙, 수당 방식이 같으면 같은 규칙이에요. 근무 이름, 색, 순서를 시작한 날짜는 따지지 않아요.
- 투표한 분 가운데 맞았어요가 정한 비율(처음 75%, 광장 › 채택 규칙에서 50~100%) 이상이어야 자동으로 채택돼요. 모자라면 검토에 남아 개발자가 정해요 [COMM-07].
- 앱의 신뢰도(0~100)는 맞았어요 비율 × 채택 점수를 채운 정도예요.
- 명세서로 맞춰 본 제보는 2점, 그 밖의 제보는 1점이에요. 다른 분의 "맞았어요"는 1점이고, 명세서로 맞춰 봤다면 2점이에요. 한 휴대폰은 한 번만 세요. "달라요"를 누른 분의 점수는 빠져요.
- 모두 1시간 안에 같은 네트워크(회사 와이파이 등)에서 보낸 설정은 자동으로 채택하지 않고 개발자가 확인해요. 한 분이 여러 번 보냈을 수도 있어서예요.
- 이미 쓰는 규칙이 있으면, 그 규칙을 고치자고 보낸 설정(토론의 "고치자는 제안"이나 `amends`를 단 제보)에 서로 다른 3명(설정 2~10명)이 맞아요 하면 다음 버전으로 바뀌어요.
- **대표 판(결정 D74, 1.25 묶음 X)**: 같은 부서의 다른 설정도 채택 조건(사람 수·맞았어요 비율)을 채우고 지지가 쓰는 규칙보다 크면 다음 버전(`source: "rival"`)이 돼요.
  지지 `support = (쓰는 휴대폰 + 보내거나 맞았어요 한 사람 + 명세서 확인 제보) × (0.5 + 윌슨 하한/200)`이고, 관리자 앱 여러 판의 추천도 같은 함수예요. 같으면 쓰던 규칙이 남아요.
  쓰던 휴대폰에는 광장 소식 `changed`가 가고, 이전 버전은 이력에 남아 앱에서 비교하고 되돌릴 수 있어요. 개발자가 거절하거나 내린 설정은 다시 모여도 자동으로 채택되지 않아요 [PLZ-02][PLAZA-05].
- 바뀐 규칙의 이전 버전은 지워지지 않고 이력(`/history`)에 남아요. 이전 버전의 토론은 읽기만 돼요 [PLZ-04].
- 채택되면 그때까지 보낸 분마다 보상이 기록되고, 자동 지급이 켜져 있으면 처음 보낸 세 분과 제안한 분께 바로 이용권(이미 결제 중이면 Play 다음 결제 미룸)으로 드려요.
  한 휴대폰이 90일(설정) 안에 자동으로 받는 보상은 3개월(설정)까지예요. 나머지는 보상 화면에 "지급 대기"로 남아요. 투표한 분께는 보상이 없어요(결정 D33) [PLZ-03].
- 채택된 규칙은 모두가 쓰는 규칙이라, 보낸 분이 되돌리거나 내 데이터를 지워도 남고 보낸 분과의 연결만 지워져요(결정 D34). 내리는 건 광장 규칙 내리기 권한이 있는 관리자만 해요.
- 토론 글에도 맞아요·달라요를 누를 수 있어요. 글의 신뢰도는 맞아요 비율이고, 세 표가 모이기 전에는 100이 되지 않아요 [PLZ-01].
- 임금표(직군·지역별 일당·시급·월급 시세)도 같은 기준(사람 수·네트워크·맞아요 비율)으로 채택되고, 이미 채택된 같은 시세의 가운데 값과 두 배 넘게 다르면 관리자가 확인해요 [PLZ-14].
- "앱에 없는 방식"으로 보낸 것은 점수에 들어가지 않고 개발자만 봐요. 개발자가 "앱에 넣을게요"로 답하면 보상을 기록할 수 있어요.

## 개인정보

- 기본급, 수당 금액, 1회 정액, 입사일, 연차, 알람, 달력 날짜는 받지 않아요. 예외는 임금표의 시세 금액 하나뿐이에요: 직군·지역·직종·단위(일당·시급·월급)·연도와 금액만 받고, 이름·회사·명세서는 받지 않아요(결정 D39 논의 중). 금액이 들어 있는 파일은 지워서 받지 않고 통째로 거절해요.
- 회사 이름, 부서, 메모, 근무·수당 이름에 전화번호, 이메일, 금액이 보이면 거절해요.
- IP 주소는 저장하지 않아요. 보내기 제한과 "같은 네트워크" 판단에는 RATE_SALT를 섞은 해시만 쓰고 2시간 안에 지워요. 그 뒤에는 같은 네트워크에서 1시간 안에 보낸 것끼리 묶는 무작위 표시만 남아요.
- 앱 설치 ID는 해시로만 남겨요. 보낸 분은 앱에서 제보를 되돌리거나 보낸 것 전부를 지울 수 있어요.
- 토론 글: 다른 사용자에게는 그 토론 안의 "참여자 N"과 올린 분·맞았어요·달라요·명세서 확인 표시만 보여요. 설치 해시는 개발자 앱에 앞 6자만 보여요.
  이메일·전화번호·금액이 보이는 글은 거절해요. 서로 다른 3명이 신고하면 개발자가 볼 때까지 가려지고, 가린 글은 90일 뒤 매시간 정리 작업(`prune`)에서 지워요. 내 데이터 지우기는 글과 신고도 지워요.
- 별명(선택, 2~12자): 고르면 토론과 규칙의 "보낸 분"에 참여자 N 대신 보여요. 관리자·개발자·운영자·밤낮은 쓸 수 없고, 비우면 지워져요.
- "쓰는 사람" 수는 앱에서 규칙을 적용한 휴대폰을 한 번씩만 세요. 내 데이터 지우기는 별명, 쓰는 표시, 글·시세에 누른 맞아요·달라요도 지워요.
- 제한: 토론 글은 설치마다 하루 20개, 네트워크마다 60개. 설치마다 하루 10건, 네트워크마다 하루 30건, 투표는 1시간에 60건, 제보 하나는 32KB까지예요. 관리자 비밀번호를 5번 틀리면 그 네트워크는 1시간 동안 잠겨요.

## 프로·결제·보상 이용권 [MON-02]~[MON-11]

- **1.28부터** 정식 출시 스위치는 은퇴했어요(`POST /api/admin/launch`는 410 `retired`). 결제·광고는 기능 관리의 `billing`·`ads` 플래그로, 처리방침 3.1 시행일·보류일과 Play 확인('확인했어요') 조건을 채우면 저절로 켜져요. 서버가 `billing`이 켜진 것을 처음 본 순간(매시 17분 작업, 확인·덮어쓰기 때마다)이 `launchedAt`이고, 다시는 바뀌지 않아요. 감사 보상 개월 수는 결제 상세에서, 무료로 연 기능은 `free.<FEATURE>` 강제 켬으로 정해요. 1.27의 `billing_live`·`free_features`·`switches_off`는 처음 한 번 덮어쓰기로 옮겨요 [FLAG-23][FLAG-25].
- 보상: 제보 보상을 '드림'으로 하면 그 휴대폰의 이용권이 1~12개월 생기고 끝 날짜 뒤에 쌓여요. 출시 전에 준 것은 출시 날부터 세요. 그 휴대폰에 구독이 있고 키가 있으면 Play 결제 미루기(`subscriptionsv2.defer`)로 대신해요(`rewards.deferred`).
- 관리자 휴대폰: 관리자 앱 › 내 정보 › '내 휴대폰 밤낮 연결'이 6자리 코드를 줘요. 관리자를 지우면 연결도 끝나요. 최고 관리자 자기 휴대폰은 바로 승인돼요. 앱은 7일 넘게 확인하지 못하면 이 이유의 프로를 쉬어요.
- 매시간 크론: 끝나기 24시간 안인 체험 구독에 '계속 쓸게요'가 없으면 Play에 다음 결제 멈춤(`subscriptionsv2.cancel`, `USER_REQUESTED_STOP_RENEWALS`, 이용자가 Play에서 되살릴 수 있음)을 요청하고 기록해요. 끝나고 30일 지난 구매 기록과 5년 지난 동의 기록(전자상거래법 시행령 제6조)을 지워요.
- `DELETE /api/mine`은 복구 코드와 관리자 휴대폰 연결을 지우고, 구매·동의 기록은 법에 따라 보관 기간까지 남겨요.
- 표는 서버가 처음 쓸 때 스스로 만들어요(`pass_codes`, `link_codes`, `admin_devices`, `subs`, `consents`, `rewards.deferred`).

## 앱 문의 [ADMIN-02]

- 설정 > 문의하기가 메일 대신 이 서버로 보내요. 개발자 앱에서 답하면 보낸 휴대폰의 문의하기 화면에 답이 보여요.
- 문의 글에 메일 주소, 전화번호, 금액이 보이면 거절해요(제보와 같은 규칙). 앱이 보내기 전에 먼저 알려 줘요.
- 함께 가는 정보는 앱 버전, 휴대폰 기종, Android 버전이고, 알람 점검 기록은 사용자가 내용을 보고 고를 때만 가요.
- 휴대폰마다 하루 5건, 네트워크마다 하루 20건, 더 묻기는 1시간에 20건까지예요. 마지막 활동 뒤 180일이 지나면 답과 함께 지워요.
- 개발자 앱 API: `GET /api/admin/inquiries?status=open|answered|closed&q=`(목록과 상태별 수), `GET /api/admin/inquiries/:id`(함께 온 정보 `context` 포함),
  `POST /api/admin/inquiries/:id/reply {text, close?}`, `POST /api/admin/inquiries/:id/status {status: open|closed}`. `/api/admin/badges`의 `inquiries`는 답을 기다리는 수예요.
- **1.29 문의 복사** [ADMCP-01]~[ADMCP-06]: 목록에 `kind=bug|question|idea|company|other`, `copied=no|yes`, `sender=<6글자>`(같은 휴대폰), 찾기 `q`는 앱 판·기기 이름·문의 번호도. 목록과 상세의 줄에 `copied: {at, by}|null`, `sender`(서버가 이미 가진 휴대폰 해시의 앞 6글자), 상세에 `sameSender`(같은 휴대폰의 다른 문의 수), 목록에 `fresh: {bugs, today}`(닫히지 않은 복사 전 문제 신고). `/api/admin/badges`에 `bugsUncopied`.
  `GET /api/admin/inquiries/export?ids=a,b`(100개까지, 문의 보기 권한, 문의를 통째로·고른 차례대로, 없어진 것은 `missing`), `POST /api/admin/inquiries/copied {ids, dev?: {title, body}, item?, assign?: true, status?: open|closed}`(문의 고치기 권한: 복사함 표시, 고르면 같은 단계에서 새 개발사항·있는 개발사항에 붙이기(개발사항 고치기 권한)·아무도 안 맡은 것 내가 맡기·상태, 활동 기록에 `inquiry_copy` 한 줄). 칸 `inquiries.copied_at`·`copied_by`와 색인 `inquiries_uncopied`는 서버가 처음 요청 때 스스로 더해요.

## 개발사항 [ADMIN-10][ADMIN-11][ADMIN-12]

- 개발자 앱 API (권한 영역 `dev`, 처리는 `devStatus`도 필요):
  `GET /api/admin/dev?status=open|todo|doing|done|rejected|all|deleted&q=&who=mine`(목록과 상태별 수),
  `POST /api/admin/dev {title, body, inquiry?}`(만들기, 문의를 주면 함께 연결), `GET /api/admin/dev/:id`(항목, 연결된 문의, 기록),
  `POST /api/admin/dev/:id {title?, body?, since?, assignee?: "me"|null, status?, reason?}`(고치기·맡기·처리, `since`가 지금과 다르면 409 `changed`로 덮어쓰지 않아요),
  `POST /api/admin/dev/:id/delete`, `/restore`(최고 관리자만), `/links {inquiry}`, `/links/remove {inquiry}`, `/notes {text}`,
  `/reply {text, ids?, close?}`(연결된 문의에 한 번에 답하기, 문의 고치기 권한 필요), `POST /api/admin/dev/bulk {ids, status, reason?}`(한 번에 처리, 100개까지).
- 반려는 이유가 있어야 해요. 모든 바꿈은 `dev_history`에 누가·언제·전과 후로 남고, 활동 기록에도 남아요.
- 문의: `POST /api/admin/inquiries/:id/assign {to: "me"|null}`, `POST /api/admin/inquiries/:id/notes {text}`, 목록 `?who=mine|free`.
  자주 쓰는 답: `GET·POST /api/admin/templates {label, text}`, `POST /api/admin/templates/:id/remove`. 메뉴 숫자(`/api/admin/badges`)에 `devTodo`, 내 것은 목록 `?who=mine`으로 봐요.
- 문의가 180일 뒤 지워지거나 앱에서 지우면 메모와 개발사항 연결도 함께 지워지고, 개발사항은 남아요.
- 표는 서버가 처음 쓸 때 스스로 만들어요(`dev_items`, `dev_links`, `dev_history`, `inquiry_notes`, `reply_templates`, `inquiries.assignee`). 지금 데이터와 관리자는 그대로예요.

설정 파일은 버전 3까지 받아요. 감시·단속 승인, 5인 미만 공휴일, 유급 휴게, 가산 대신 받는 수당을 쓴 설정만 3이 되고, 나머지는 예전 앱도 읽는 2로 남아요.

## 로컬에서 해 보기

Node 22 이상이 있으면 Cloudflare 없이 돌려 볼 수 있어요.

```sh
cd server/company-worker
npm test
ADMIN_PASSWORD=<10자 이상> npm run local -- 8788 --seed
```

`--seed`는 지어낸 회사들의 제보와 관리자(승인된 민지, 승인 대기 준호, 가입 전 초대 하나)를 넣어서 모든 화면에 뭔가 보이게 해요. 민지는 `minji@example.com` / `minji-review-2026`으로 로그인해요. 개발자 앱은 `http://localhost:8788/admin/`에서 열려요. `--seed`는 최근 56일 사용 통계도 넣어 통계 그래프가 비지 않아요.

개발자 앱 화면 시험은 브라우저 흉내(happy-dom)가 필요해서 따로 돌려요. 화면마다 인라인 style이 없는지, 거른 상태가 주소에 남는지, 로그인이 끊겨도 쓰던 답이 남는지, 여러 개 처리와 되돌리기, 단축키와 명령창, 기기 설정을 봐요.

```sh
npm ci
npm run test:ui
```
