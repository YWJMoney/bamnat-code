# 1.30 AP1 앱 조회 경로와 캐시

추적표 접두사 `SPD-` (SPD-11 ~ SPD-19). 사진 1450 ~ 1461. 서버 쪽은 SP1(SPD-01 ~ SPD-10).

## 사용자 요청 (2026-10-27)

- "여전히 조회하는 로딩이 너무 느리다. 획기적으로 속도를 빠르게. 느려서 사용에 거부감이 생길 수 있다. 아주 중요한 문제."

## 원인 (앱 쪽)

1.29의 앱은 화면을 열 때마다 서버에 물었고, 한 화면에 요청을 여러 번 차례로 보냈다. 회사 화면은 페이지를 받은 뒤 방을 두 번 읽었고, 정보 광장은 토론과 방을 열 때와 시트를 닫을 때 다시 읽었다. 검색은 글자가 멈출 때마다 서버에 물었다. 이 설정 쓰기는 참여, 페이지, 방을 차례로 기다렸다. 본 화면을 기억하는 곳은 메모리뿐이라 앱을 다시 열면 늘 스피너부터 보였다. 연결 제한 시간 15초는 안 되는 망에서 너무 오래 기다렸다.

### 전체 목록 [SPD-11][SPD-12]

- `GET /api/companies/all`을 앱 시작·광장·찾기를 열 때 IO에서 받아 `cacheDir/company_all.json`에 ETag와 같이 둔다. 10분이 지나면 If-None-Match로 다시 묻고 304면 그대로 쓴다.
- `CompanySearch.find`는 서버 검색과 같은 규칙으로 찾는다: 이름·다른 이름의 정규화 포함, 읽기(`CompanyMatch.spoken`), 초성, 같은 정렬(이름 그대로, 쓰는 규칙, 시작, 짧은 것, 이름순), 20개.
- `peek().enough`면 서버에 묻지 않는다. 목록에 없는 이름은 한 번 묻는다(목록 뒤에 생긴 회사).
- 옛 서버(404)는 1.29처럼 많이 쓰는 회사 목록.

### 디스크 PageCache [SPD-13]

- `cacheDir/plaza_cache.json`(백업 안 됨), 서버 JSON 그대로 저장하고 같은 파서로 읽는다. 14일 지나면 버림. 회사 8개·규칙 광장 첫 쪽 6개·토론 6개 LRU.
- 쓰기는 0.5초 모아 tmp 파일 + rename. 읽기·쓰기 모두 IO, 화면 실에서 디스크를 만지지 않는다.
- 내 활동은 설치 번호 대신 그 해시로 표시하고, 내가 보낸 시세 금액(rates)은 두지 않는다.
- 회사 화면은 참여 여부가 같을 때만 방·토론을 같이 둔다. 비참여자로 읽은 페이지는 방을 지운다.
- 화면: 있으면 바로 보이고 위에 얇은 줄(`RefreshLine`). 새로 읽기에 실패하면 "최근 본 내용이에요. 인터넷이 되면 새로 불러와요." + 다시 시도.

### 한 요청 묶음 [SPD-14]

- `CompanyApi.companyBundle(id, device)`: 기본은 `CompanyException(CompanyBundle.NONE)`. 화면은 확장 `CompanyApi.bundle()`을 부른다. NONE이면 페이지·방·토론을 나란히 읽어 묶는다. 시험용 위임 래퍼(`CompanyApi by base`)가 기본 구현을 그대로 넘겨도 래퍼의 `company`·`room`·`talk`가 쓰인다.
- 클라이언트는 `?with=room,talk`. 답에 room·talk 키가 없으면(옛 서버) 방·토론을 나란히 읽는다.

### 미리 읽기 [SPD-15]

- 찾기 결과·규칙 광장 탭에서 아직 없는 첫 3곳을 0.4초 뒤 X-Device 없이(공개 읽기) 한 번만. 참여자 읽기 한도에 들지 않는다.

### 쓰기 먼저 보이기 [SPD-16]

- 글: "보내는 중"으로 바로 보이고, 실패하면 빼고 이유를 말한다.
- 투표: 서버가 준 수로 바로 고치고 페이지는 뒤에서.
- 이 설정 쓰기: 참여 요청에 `"with":"page"`를 실어 그 답의 페이지를 쓴다. 진행 중인 읽기가 있으면 다시 읽지 않고 기다린다.
- 토론 시트를 닫으면 시트가 마지막에 읽은 토론을 그대로 쓴다. 바뀐 것이 없으면 아무것도 읽지 않는다.

### 조회 속도 카드 [SPD-17]

- `NetTimings`: 경로 종류(검색·회사·광장·토론·쓰기·기타)와 걸린 시간만, 최근 50개, 메모리에만. 어디에도 보내지 않는다.
- 자가 점검 "조회 속도": 보통·가장 느림, 2.5초 넘는 응답, 연결 안 됨, 바로 보인 화면 비율, 화면별 기다림(찾기·회사·광장).

### 서버 세션 [SPD-18]

- 답의 `x-d1-bookmark`(출력 가능 200자 이하)를 다음 요청에 돌려준다. 클라이언트 객체마다 하나, 디스크에 두지 않는다.
- 쓰기 뒤 30초 안의 GET은 `Cache-Control: no-cache`(SP1 보관본 건너뛰기).

### 스스로 찾은 것 [SPD-19]

- 연결 제한 6초(15초였음). 읽기 제한은 그대로.
- 데이터 절약을 "요금제 연결"로 보지 않는다. 휴대폰의 데이터 절약이나 절전이 켜졌을 때만 미리 읽지 않는다.
- 방 카드 계산을 화면 실 밖(Default)에서.
- 약관·광장 목록은 하루 보관, 규칙 광장 첫 쪽이 보관본일 때 아래 로딩 표시를 숨김.

## 결정

- 캐시는 cacheDir에만. 달력·기기마다 섞이지 않게 키를 나눈다(회사 id, 광장 키, 내 활동은 설치 해시). 급여 금액 같은 개인 값은 두지 않는다.
- Room DB(21)·권한·개인정보 처리방침 변경 없음. 서버로 새로 보내는 값: 참여 요청의 `"with":"page"`, 요청 헤더 `x-d1-bookmark`(서버가 준 값을 되돌림)·`Cache-Control: no-cache`, 페이지 요청의 `?with=room,talk`. 모두 기기와 이어지지 않는다.
