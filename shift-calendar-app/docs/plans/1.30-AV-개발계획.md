# 1.30 AV 개발계획: 사진마다 같게 읽기, 명세서로 통상임금 기준 시간 찾기

추적표: PHOTO-20 ~ PHOTO-29, HOURLY-01 ~ HOURLY-03.

사용자 말(2026-10-27):
- "명세서를 전보다는 잘 읽지만 사진마다 읽는 부분이 다르다. 정확도 향상"
- "LG화학은 근로시수 180시간으로 통상임금이 적용된다. 명세서와 규칙 사진만으로 월급을 정확하게 계산해 내야 한다."

결론부터 말하면 두 가지 다 됐어요.
- 같은 명세서를 486가지 방식으로 찍어 봤어요. 돌리고, 옆에서 찍고, 가까이·멀리 찍고, 위아래를 자르고, 단어를 쪼개고, 머리글을 지운 사진이에요. 방식마다 2장씩, 3번씩 읽었어요.
  - 항목 99.7%(22,945/23,004), 시간 99.9%를 맞혔어요.
  - 노란 줄이 아닌데 틀린 줄(조용히 틀림)은 0이에요.
  - 이번 고침을 하나씩 넣기 전에는 같은 격자에서 조용히 틀린 줄이 129개였어요(쪼개진 이름·금액, 두 번 적힌 합계).
- 화학 공장 명세서 한 장만으로 통상임금 기준 시간 180시간을 찾아요. 계산식은 이래요.
  - (기본급I 2,397,500 + 기본급II 158,330 + 자격수당 57,500 + 상여 600%의 1/12 1,277,915) ÷ 통상시급 21,618.04 = 180시간
  - 2.2원 차이가 남아요.
  - 규칙 사진의 '통상임금 산정 기준시간 180시간' 같은 문장도 읽어요.

## 2. 정한 것

- 사진은 저장소에 넣지 않았어요. 시험은 글자 상자 자료(PlantSample)만 써요. 변형은 그 상자를 원근·회전·크기·자르기·쪼개기로 흔들어 만들어요.
- 명세서 틀은 폰 안의 read_fixes 파일에만 둬요. 서버로 가지 않고, 금액은 들어 있지 않아요.
- 새로 서버로 가는 것은 '사진이 달라요' 이유 코드 두 개(hourly, hours)뿐이에요. photo.wrong 깃발이 꺼져 있으면 지금처럼 폰에만 모아요.
- 상자 흔들림은 사진 크기에 비례하게 바꿨어요. 크기 ×1에서는 1.29와 같은 난수 순서예요.
- 노란 줄이 4개 넘는 장의 비율은 4.0%(39/972)예요. 공제 줄 하나가 틀리거나 빠지면 공제 합계로 나머지를 검산할 수 없어요. 그러면 열 위치로만 놓은 이름(볼링회(남부공장)처럼 사전에 없는 이름)이 함께 노래져요. 시험 기준은 5% 이하로 두었어요.
