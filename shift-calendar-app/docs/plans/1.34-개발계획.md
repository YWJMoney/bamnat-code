# 1.34.0 개발계획 (나눔 판 기반)

사용자 지시(2026-10-29 22:12Z, 1.34 설계서 7장 답):

1. 저장소 비공개: "코드가 공개되면 안되니깐 처리방침 공개 자료만 공개를 해야해".
2. 회사 규칙 광장의 맞아요·달라요는 그대로. 레시피와 이야기는 좋아요·안좋아요.
3. 새 휴대폰의 첫 레시피 3개는 검토 뒤 공개 (설명함, 다른 말 없으면 그대로).
4. 안좋아요 수는 보이게. 대신 "의견을 달게 해주기 왜 안좋은지 만든사람이 바꿀수 있도록".
5. "설계서에 있는 개선점 혁신점 전부를 진행 … 1.34에는 기반을 다지고 1.35에 나머지 모든 기능을 누락없이 개발을 진행한후 직접 조작을 해보고 상호작용까지 … 온전한 개발 완료 까지".

근거(비공개 프로젝트 파일): `계획/1.34-나눔판-설계서.md`. 순번은 설계서 6장 제안(743~787)에서 743·744가 1.33 빌드 확인에 쓰였으므로 745부터 다시 매겨요.

판 정보: 1.34.0(versionCode 46, 워치 100046), DB 24. main(1.33.0 합침, 0559b5f)에서 새로 시작해요.

## 정한 것

- **D106 레시피는 값만 담아요.** 조각 사전(core `recipe/PieceCatalog`)에 있는 칸만 읽고 나머지는 버려요. 식·스크립트·링크·그림 주소는 없어요. 계산은 늘 앱 안의 엔진이 해요(설계서 4-7 S1, 4-8).
- **D107 안좋아요는 이유를 꼭 달아요(사용자 4번).** 이유 칩 하나(설명이 부족해요 / 내 달력에서 이상해요 / 비슷한 게 이미 있어요 / 쓰기 어려워요 / 그 밖의 것)와 짧은 의견(5~120자, 연락처·금액·링크 거름)이 있어야 보내져요. 안좋아요 수는 모두에게 보이고, 이유(칩과 의견)는 누가 적었는지 없이 만든 사람에게만 보여요(만든 사람이 고칠 수 있게, 처리방침 3.8 초안과 같게). 부적절한 내용은 안좋아요가 아니라 신고로 안내해요. 몰이 대응은 신뢰 단계 가중치·같은 네트워크 묶음 보류로 해요(순위에만, 보이는 수는 그대로).
- **D108 첫 레시피 3개 검토(사용자 3번).** 이 휴대폰이 처음 올리는 공개 레시피 3개는 검토 대기(`pending`)로 들어가고, 관리자가 공개·돌려보내기를 해요. 24시간이 지나면 관리자 앱 오늘 할 일 맨 위로 올라와요. '링크로만'·'나만'은 검토 없이 바로 쓸 수 있어요(광장 목록에 안 나오므로).
- **D109 처리방침 3.8은 1.35까지 한 번에.** 나눔 판 전체(레시피, 좋아요·안좋아요와 이유, 이야기, 적용·유지 합계, 구독·팔로우, 요청 판, 표지 그림)를 3.8 하나에 적어 30일 예고를 한 번만 해요. 서버로 보내는 기능은 `recipe.publish`·`recipe.vote`·`recipe.talk`(LEGAL, 3.8 날짜 조건) 뒤에서만 켜져요. 받기·미리 보기·적용은 공개 목록을 읽기만 하므로 먼저 열 수 있어요(`recipe.browse`, 일반 플래그).
- **D110 저장소 나누기.** 코드 저장소는 비공개로, 처리방침·약관·커뮤니티 규칙·공개 자료(`remote/`)만 새 공개 저장소 `-`로 옮겨 주소(`ywjmoney.github.io/-/…`)를 그대로 둬요. 사용자가 이름 바꾸기·비공개·새 저장소·Pages를 하고, Claude가 공개 파일만 올려요(`release/1.34.0/시작-전-할-일.md`). 2026-10-29 22:23Z 사용자가 코드 저장소를 `YWJMoney/bamnat-code`(비공개)로 바꾸고 공개 저장소 `YWJMoney/-`를 만들었어요. 처리방침·약관·커뮤니티·`remote/` 고침은 이제 공개 저장소에도 PR로 올려요(처리방침 3.8 초안 `YWJMoney/-` #1). 비공개 저장소는 Actions가 한 달 2,000분이라 CI를 줄여요(REPO-01).
