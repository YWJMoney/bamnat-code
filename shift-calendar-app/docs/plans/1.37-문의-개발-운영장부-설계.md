# 1.37 문의·개발 운영 장부: "나는 전달만, 처리는 Claude가" (설계 1판)

작성 2026-11-03, 프로젝트 스레드 "문의와 개발을 Claude로 바로 처리하기 조사". 순번 **DESK-01~DESK-14**(추적표에 대기로 올림).
코드는 아직 고치지 않았어요. 1.37 '한 줄 운영 체계'(`1.37-한-줄-운영-체계-설계.md` 2-2~2-5, PR #152 브랜치와 프로젝트 파일 `조사/`)를 이 흐름으로 구체화하고, 1.36 F 갈래 할 일함(PR #148 `work.js`) 위에 쌓아요.

## 사용자 요구 (2026-11-03, 원문 요약)
> 1.37 개발 사항에 넣는다. 문의·개발 요청·버그·개선 요청 등이 들어오면 **모든 내역을 관리하는 체크시트**가 있어야 하고, 문의가 **이전에 개발된 사항과 겹치는지 비교**할 수 있어야 하고, **내가 Claude에게 전달하는 방식이 아주 편해야** 하고, Claude는 **개발이 끝난 뒤 체크시트와 개발 모든 사항을 업데이트해 처리를 진행**할 수 있어야 한다. **나는 전달만 하고 문의 답변까지 모든 것은 Claude가 처리**한다.

함께 정해진 것: **처리방침은 바꾸지 않아요**(2026-11-03). 그래서 서버가 문의 글을 새로운 곳(Claude API, GitHub 이슈)으로 보내지 않아요. Claude는 지금 'Claude에게 넘기기'와 같은 길(사용자님의 Claude 프로젝트)로만 읽어요.
앞선 조사: 프로젝트 파일 `조사/1.37-문의-개발-Claude-직접처리-조사.md`, `조사/1.37-문의-개발-현방식-검토.md`(문제점 P1~P13, 개선 I1~I10, 혁신 X1~X5).

## 2. 운영 장부 (체크시트) — DESK-02, DESK-03

관리자 앱 새 화면 **'운영 장부'**. 1.36 할 일함을 표로 넓힌 것이에요(할 일함 = 장부의 '오늘 할 것' 거르기).

### 한 줄의 칸
| 칸 | 내용 |
|---|---|
| 번호 | `K-0001`처럼 짧게(사람이 말로 부르기 쉽게). 안쪽은 지금 문의 id·개발사항 id와 이어짐 |
| 들어온 날 · 종류 | 문의(질문·문제·제안·회사 방식)·스튜디오 요구·신고·사진·관리자 메모 |
| 요약 | 한 줄(Claude가 씀, 원문은 눌러서) · 화면 경로(앱이 문의 앞에 붙이는 `[설정 > …]`) · 앱 판 |
| 겹침 | 후보 3개까지: 이전 개발사항(상태·나간 판), 같은 문의, 자주 쓰는 답 + 점수와 이유("같은 화면 · '알람 소리'") |
| 묶음 | 확정된 개발사항 `d…`(같은 개발사항에 묶인 건수) |

### 상태 단계 (DESK-04)
`접수 → 분류됨 → (답으로 끝 | 개발 대기) → 개발 중(PR #) → 코드 고침·확인 전(빌드) → 에뮬레이터 확인됨 → 출시 대기(판) → 출시됨 → 답 보냄 → 효과 확인 → 닫힘` / `반려`·`중복`·`스팸`
- 앱의 내 문의에는 지금처럼 '접수·확인 중·답변·개발 목록·만드는 중·반영' 여섯만 보여요. **'반영'은 출시됨일 때만**(DESK-01).
- 닫을 때 이유는 꼭(1.36 할 일함 이유와 하나로: 답함·중복·이미 고침·개발로 넘김·하지 않기로 함·스팸·문제없음).
- 닫힌 줄에 같은 신호가 다시 오면 '다시 열림'(1.36 할 일함 규칙 그대로).

### 보는 법
- 거르기: 오늘 할 것 · Claude 차례 · 사용자 확인 필요 · 개발 중 · 출시 대기 · 기한 넘음 · 종류 · 판.
- 데스크톱은 표, 휴대폰은 카드 한 줄. CSV 내보내기(프로젝트 파일 `운영/`에 주간 사본을 Claude가 둠).
- 정리함(1.35 일곱 묶음)은 장부 안의 '겹침 판단'으로 들어가고 화면은 하나로 합쳐요(P11).

## 3. 겹침 비교 — DESK-05, DESK-06

새 줄이 들어오는 순간 서버가 비교해 **후보와 이유**를 칸에 적어요. 확정은 Claude(또는 사용자)가 해요.

| 비교 대상 | 지금 | 1.37 |
|---|---|---|
| 개발사항(모든 상태, 나간 판 포함) | 글자 비슷함(dice 0.42) | + 같은 뜻 낱말 사전(알람=알림=울림=소리, 급여=월급=임금…) + **별칭 배우기**: Claude·사용자가 다른 개발사항으로 옮겨 묶으면 그 낱말을 그 개발사항의 별칭으로 저장 |
| 이전에 답한 문의 | 같음 | 같음 + 화면 경로 일치 가산 |
| 출시 노트(판마다 고친 것) | 없음 | 개발사항의 '나간 판'으로 연결 → "1.36.0에서 고친 것과 겹침" |
| 같은 기간 새 문의끼리 | 묶음 | 같음 + 우선순위 점수(연결 수 + 나도 그래요 × 종류 무게 × 최근 늘었나) |

- '다시 생김'(고친 판 이상인데 또 옴)은 장부 맨 위 + 관리자 휴대폰 급한 알림(P10).
- 서버 비교는 사람 없이 **답을 보내지 않아요.** 자동 대응(1.35)은 장부의 'Claude 처리'로 대신하고, 남겨 둘 때도 점수 높을 때만·10분 보류(DESK-01 함께).

## 4. 사용자 → Claude 전달 (아주 편하게) — DESK-07, DESK-08

1. **기본: 아무것도 안 해도 돼요.** 새로 들어온 모든 줄은 저절로 'Claude 차례'예요.
2. **처리 시작은 한 마디**: 프로젝트 채팅에 **"처리해"**(또는 "문의 처리해"). Claude가 장부를 직접 읽어요(복사·붙여 넣기 없음).
3. **매일 자동(선택)**: 매일 아침 정한 시각에 Claude가 스스로 한 바퀴 돌고 보고만 올려요. 켜고 끄기는 사용자님이.
4. **특별히 짚고 싶을 때**: 관리자 앱(휴대폰)에서 그 줄에 '급해' 별 또는 한 줄 메모("이건 환불로 답해 줘") → Claude가 그 말대로.
5. 여러 건을 한 번에 넘기고 싶으면 장부에서 골라 'Claude에게' 한 번.

**연결 방법: Claude 운영 열쇠** (DESK-07)
- 관리자 앱 › 관리자 › '운영 열쇠 만들기'(주인만). 열쇠 하나 = 'Claude' 관리자 하나(기록에 'Claude'로 남음).
- 사용자님은 열쇠를 Claude 프로젝트 설정 › 클라우드 환경 › 비밀값(Network secrets, 없으면 환경 변수)에 `BAMNAT_OPS_KEY`로 한 번 넣어요. **채팅에 붙여 넣지 않아요.** 클라우드 환경 네트워크에서 `api.bamnat.app`를 허용해야 해요.
- **'직접 읽는다'는 뜻**: Claude 스레드는 클라우드 컴퓨터에서 명령을 실행할 수 있어서, 사람이 관리자 앱을 여는 대신 `https://api.bamnat.app/api/admin/desk?who=claude` 같은 관리자 API 주소를 열쇠와 함께 불러 장부를 글(JSON)로 받아요. 답 보내기·상태 바꾸기도 같은 API에 보내요. 지금 관리자 API는 브라우저 로그인 쿠키(`x-admin`)로만 열려서 이 열쇠 인증은 DESK-07에서 새로 만들어요. 열쇠가 없거나 네트워크가 막힌 동안은 지금처럼 'Claude에게 넘기기' 붙여 넣기로 돌아가요.
- 계정을 바꾸면 새 계정의 프로젝트에 열쇠만 다시 넣으면 돼요(1분). 옛 열쇠는 관리자 앱에서 끊어요.
- 열쇠로 할 수 있는 것: 장부·문의·개발사항 읽기, 분류·요약·겹침 확정, 개발사항 만들기·묶기·상태·메모·PR·빌드·PC 결과, **문의 답 보내기**(아래 규칙), 판 묶기·출시됨 표시, 효과 확인 기록.
- 할 수 없는 것: 지우기, 사용자 제한·글 가림 풀기, 기능 스위치·설정·공지, 관리자 계정, 보상·결제 처리, 사진 원본 내려받기. 90일 기한, 바로 끊기, 하루 요청 수 한도, 모든 동작 기록.

## 5. Claude가 하는 처리 — DESK-09~DESK-12

### 5-1. 한 바퀴 (Claude의 고정 순서)
1. 장부에서 'Claude 차례'와 '급해'를 읽어요(급해 → 기한 가까운 순 → 점수 순).
2. 한 줄마다: 요약 쓰기 → 겹침 후보 확인·확정(틀린 후보는 고쳐서 별칭 배우기) → 아래 셋 중 하나.
   - **답으로 끝**(질문·이미 고침·개발 목록에 있음·자주 묻는 것): 답을 써서 보냄 → '답 보냄', 닫기 이유.
   - **개발로**: 새 개발사항 또는 기존 개발사항에 묶기 + 문의한 분께 "개발 목록에 올렸어요" 답 → '개발 대기'.
   - **사용자 확인 필요**(5-3): 답 초안과 추천을 붙여 사용자님께 고르기 카드.
3. '개발 대기'가 있으면 갈래를 정해 개발 스레드를 열어요(지금 방식: 작업 스레드 → PR → 디버그 빌드 → PC 확인). 장부 상태는 Claude가 단계마다 올려요.
4. 끝나면 보고 한 장: 처리 N건(답 N, 개발 N, 묶음 N), 사용자 확인 필요 N, 기한 넘은 것, 다시 생김.

### 5-2. 개발이 끝난 뒤 (DESK-10, '출시가 답한다')
- PR이 열리면 `개발 중(PR #)`, 합쳐지면 `코드 고침·확인 전`, PC 확인 결과가 오면 `에뮬레이터 확인됨`. Claude가 열쇠로 올리고, PR 본문에 `d…`를 적어 GitHub 웹훅(GitHub → 서버로 PR 번호·제목·d… id만)으로도 저절로 맞춰요(DESK-11, 선택).
- 사용자님이 Play에 올린 뒤 **"1.37.0 나갔어"** 한 마디(또는 관리자 앱 '나간 판' 저장) → Claude가 그 판의 개발사항을 `출시됨`으로, 묶인 문의 모두에 "1.37.0에서 고쳤어요, 업데이트해 주세요" 답 → 앱 '반영' → 닫기.
- 저장소도 함께 갱신: 추적표 상태·근거, `HANDOFF.md` 맨 위 판, 출시 노트의 '고친 것'에 개발사항 번호.
- 7일·14일 뒤 효과 확인: 그 개발사항에 겹치는 새 문의·다시 생김을 출시 전과 비교 → '효과 확인됨' 닫기 또는 다시 열기(DESK-12).

### 5-3. Claude가 혼자 보내지 않고 사용자님께 묻는 것 (DESK-09)
- 환불·결제·구독·보상 지급, 법·안전 신고(불법촬영물·명예훼손·청소년), 개인정보 지우기·열람 요청, 화가 크게 난 민원·분쟁, 약관·처리방침에 관한 질문, 회사 이름이 나오는 회사 방식 공개 여부, 큰 방향이 바뀌는 개선 요청(1.37 범위 밖).
- 묻는 법: 한 번에 모아 고르기 카드(추천 하나와 답 초안). 고르면 Claude가 보내요.

### 5-4. Claude 답 규칙
- 말투: 지금 자주 쓰는 답과 같은 쉬운 존댓말, 결론부터, 사실만(확인 전이면 "확인 중"·"다음 업데이트에 들어가요", '고쳤어요'는 출시됨일 때만).
- **10분 보류**: 보낸 답은 10분 동안 '보류 중'으로 장부에 남고, 그 사이 사용자님이 휴대폰에서 취소·고치기 가능. 그 뒤 앱으로 가요(문의 답 바로 알림 그대로).
- 하루 보내는 답 수 한도(처음 30, 사용자님이 바꿈). 넘으면 멈추고 보고.
- 답에 링크는 밤낮 공식 주소만, 전화·메일 주소·결제 유도 없음(서버가 한 번 더 거름).
- 보낸 사람 표시는 지금처럼 '운영자'(기록에만 'Claude').

## 6. 먼저 고칠 것 — DESK-01 (1.37 첫 일)
- '고친 판'과 '나간 판' 나누기: 관리자 앱에 'Play에 나간 판' 한 칸. 개발사항 완료 판이 그 이하일 때만 '이미 고침'·앱 '반영'. 지금은 결과 `완료 1.37.0`만 적어도 앱에 "1.37.0 반영"이 뜨고, 자동 대응이 켜졌으면 출시 전에 "업데이트하세요"가 나가요(`inbox.js` `classify()`, `inquiries.js` `inquiryProgress()`).
- 자동 대응 안전장치(점수 ≥ 0.6·같은 주제·10분 보류·하루 한도). 그 전까지 실서버 자동 대응 '이미 고침'은 끄기를 권해요.
