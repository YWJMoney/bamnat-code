## 0. 결론 먼저

1. **지금 바로 고칠 버그가 하나 있어요.** 개발사항을 `완료 1.37.0`으로 적는 순간, 아직 Play에 안 나왔는데도 (a) 앱의 내 문의에 "1.37.0 반영"이 뜨고, (b) 자동 대응이 켜져 있으면 같은 문의를 보낸 사람에게 "1.37.0에서 고쳤어요, Play에서 업데이트하세요"가 저절로 나가요. '고친 판'과 '나간 판'이 한 칸이라서예요. **고치기 전까지 자동 대응(이미 고침)은 꺼 두기를 권해요.**
2. **가장 큰 불편은 복사·붙여 넣기 두 번**(넘길 때, 결과 받을 때)과, **고친 뒤 '출시됐다'는 순간이 시스템에 없는 것**이에요. 그래서 문의한 분께 정확한 때에 답이 못 가요.
3. **혁신 방향은 "출시가 답한다"**: PR과 출시 판이 개발사항 상태를 저절로 올리고, 실제로 Play에 나간 날 묶인 문의 모두에 답 초안이 한꺼번에 준비돼요. 문의 글은 어디로도 새로 가지 않아요.

## 1. 지금 흐름 (한 바퀴)

```
앱 문의 → 서버 저장(글·버전·모델·Android, 사진, 알람 점검 등)
  → 정리함: 글자 비슷함(dice ≥ 0.42)으로 7묶음 (이미 고침·목록에 있음·다시 생김·반려·전에 답함·자주 쓰는 답·새 문제)
  → (주인이 켜면) 자동 대응: 이미 고침·목록에 있음은 사람 없이 답
  → 새 문제는 묶어서 개발사항 만들기
  → 'Claude에게 넘기기': 넘기지 않은 개발사항을 글 한 덩어리로 복사 → 프로젝트 채팅에 붙여 넣기 ①
  → Claude 스레드가 고치고 PR → PC 에뮬레이터 확인 → 사용자가 합치기 → 출시
  → Claude가 쓴 '결과' 줄(d… 완료 1.37.0)을 관리자 앱에 붙여 넣기 ② (원하면 묶인 문의에 한꺼번에 답)
```

## 3. 개선점 (처리방침 그대로, 작은 것부터)

| # | 개선 | 고치는 문제 | 크기 |
|---|---|---|---|
| I1 | **'고친 판'과 '나간 판' 나누기**: 관리자 앱에 "Play에 나간 판"(예: 1.36.0) 한 칸. 개발사항 완료 판이 그 이하일 때만 '이미 고침'·앱 '반영'. 그 전에는 '다음 업데이트에 들어가요'(known 문구) | P1 | 작음 · **먼저** |

## 4. 혁신점

### X1. 출시가 답한다 (추천 1순위)
```
PR 본문에 d… 적기 ─(GitHub 웹훅: PR 번호·제목·d… id만)→ 서버
  PR 열림 → '개발 중(PR #)'      PR 합침 → '코드 고침, 확인 전'
PC 확인 결과 → '에뮬레이터 확인됨'(관리자 앱 한 번 누름 또는 아래 X2 토큰)
관리자 앱 "Play에 나간 판 = 1.37.0" 저장 → 그 판의 개발사항 모두 '출시됨'
  → 묶인 문의 모두에 "1.37.0이 나왔어요, 업데이트해 주세요" 답 초안이 한 화면에 → 한 번 눌러 보냄
  → 앱 내 문의 '반영' + 새 소식(이미 있는 WHATS_NEW 연결)
```
- 문의 글은 GitHub로 가지 않아요. 웹훅은 GitHub에서 **서버로** PR 번호·제목·d… id만 들어와요(서버가 GitHub를 부르지 않음, 받는 쪽 서명 확인 값만 Secret). 처리방침의 보내는 정보·받는 곳은 그대로예요.
- 결과 붙여 넣기 ②가 사라지고, P1·P4·P5가 한꺼번에 풀려요.

### X2. 넘기기도 한 번에 (붙여 넣기 ① 없애기)
- 관리자 앱에서 **'개발 연동 열쇠'**(권한 좁은 토큰: 넘김 글 읽기, 개발사항 상태·메모 쓰기만, 답 보내기·삭제 없음, 90일, 바로 끊기)를 만들어 Claude 환경 변수에 넣으면, Claude 스레드가 넘김 글을 직접 읽고 상태를 직접 올려요.
- Claude가 읽는 내용은 지금 붙여 넣는 것과 같아요(I6으로 오히려 줄어듦). 새 받는 곳 없음.
- 사용자님은 프로젝트 채팅에 "넘긴 것 처리해" 한 줄이면 돼요.

### X3. 보내기 전에 답 (문의 자체를 줄이기)
- 앱의 문의 쓰기 화면에서, 휴대폰이 이미 받는 '모두의 문의'·도움말과 함께 **이미 고친 문제·개발 중 목록(제목과 판만)**을 하루 한 번 받아 두고, 쓰는 글과 **휴대폰 안에서** 맞춰 봐요. 맞으면 "이 문제는 1.37.0에서 고쳤어요 · 업데이트" / "개발 중이에요 · 나도 그래요 누르기"를 보내기 전에 보여 줘요.
- 쓰는 글은 휴대폰 밖으로 안 나가요(보내기를 누를 때만 지금처럼). 받는 목록은 관리자가 공개해도 된다고 표시한 개발사항 제목만.
- 같은 문의가 줄고, '나도 그래요'가 모여 우선순위(I5)가 정확해져요.

### X4. 효과를 저절로 확인
- 출시 7일·14일 뒤, 그 개발사항에 맞는 새 문의 수(정리함 판단 그대로)와 '다시 생김'을 출시 전과 비교해 카드에 붙여요. 줄었으면 '효과 확인됨'으로 닫기 제안, 그대로면 다시 열기.
- 1.37 '한 줄 운영 체계' 2-5와 같은 칸이에요.

### X5. 기능 id → 코드 지도
- 정리함 주제(`triage` topic)와 화면 경로를 기능 id로 바꾸고, 저장소에 "기능 id → 코드 위치" 표를 둬요. 넘김 글에 기능 id가 붙으면 Claude가 바로 그 파일부터 봐서 고치는 시간이 줄어요. (관측 설계안의 '찾았는데 없음 = 기능 id'와 같은 목록)
