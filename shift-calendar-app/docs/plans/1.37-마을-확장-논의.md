# 마을 커뮤니티 확장 논의 (1판)

작성 2026-11-01, '마을 커뮤니티 확장 방향 논의' 스레드. 논의용이에요. 코드는 아직 고치지 않아요.
아이디어 출처는 모두 사용자 관찰·공개 정보예요(CLAUDE.md 5항).

## 1. 지금 마을에 이미 있거나 정해진 것 (1.36)

| 묶음 | 들어간 것 | 근거 |
|---|---|---|
| 광장 | 유형별 광장(회사 정보 광장은 익명 번호, 규칙·교대/일근 광장, 알바·현장 시세+이야기, 자영업·투자 이야기), 꼬리표(질문·팁·자랑), 도움 됐어요, 투표, 이번 주 주제, 야간 거르기·깨어 있는 분 수, 간직, 자랑 글에 작품 카드 | 조사 V8~V13·V16 |
| 시세 | 직군·지역별 일당·시급·월급 시세(서로 다른 휴대폰 수가 차야 공개, 관리자 채택) | 서버 index.js 광장 시세 |
| 장터·공방 | 테마/기능별 구간, 입어 보기, 넘겨 보기, 스튜디오에서 고치기, 요청→스튜디오→완성, 오래 써요%, 새 창작자 자리, 이달의 주제 공모(뽑히면 프로 30일, 1년 365일 상한) | V14~V19, 902 |
| 사람 | 마을 이름 하나, 창작자 프로필·팔로우·피드·모음·통계·이달의 제작자, 새싹·이웃·단골 믿음 단계 | 프로필 설계, V3·V20 |

**정리하면** 1.36 마을은 "근무 유형 6개로 나뉜 큰 광장 + 창작자 장터"예요. 아직 **없는 것**은 ① 유형보다 작은 '같은 일 하는 사람' 묶음, ② 커뮤니티가 함께 다듬는 오래 남는 정보, ③ 함께 무언가를 하는 활동, ④ 사람 사이의 직접 연결(쪽지·모임)이에요.

## 2. 확장 선택지

난이도 소·중·대, 안전·운영 부담 낮음·중간·높음. 밤낮만 할 수 있는 점(근무표를 안다)을 살린 것을 우선했어요.

### A. 직업 모임: 유형 안에 '같은 일' 방 (추천 ★★★)
- **무엇**: 교대 안에 간호·경찰·소방·생산직·보안, 알바 안에 편의점·카페·배달·물류 같은 **직종 방**. 처음 고를 때 하나(바꿀 수 있음), 광장 칩 하나로 '전체 | 내 직종'.
- **방은 관리자 앱이 정한 목록만**(사용자가 방을 만들지 않음). 글이 적은 방은 위 유형 광장에 같이 보여 빈 방이 안 생기게.
- **왜**: 지금 '교대'는 간호사와 공장 3조2교대가 섞여 질문이 안 맞아요. 시세 직군 칸을 그대로 씀.
- **안전·운영**: 낮음. 기존 신고·단계 제한·차단 그대로. 방 목록만 관리.
- **난이도**: 중(서버 방 꼬리표 + 관리자 방 목록).

### B. 함께 다듬는 정보 모음 (추천 ★★★)
- **무엇**: 직종·유형별 '알아 두면 좋은 것' 한 장(야간 수당 계산, 연차 생기는 법, 알바 주휴수당, 자영업 부가세 달력…). 광장 '도움 됐어요' 많이 받은 답과 문의 정리함의 '자주 묻는 질문'을 관리자가 골라 한 장에 붙여요. 사용자는 '고칠 점 제안'만, 고치는 건 관리자 확인 뒤.
- **급여 화면과 이어 주기**: 급여·연차 화면의 '왜?' 단추가 그 정보 한 장으로. 반대로 정보 한 장에서 '내 급여로 계산해 보기'.
- **왜**: 이야기 글은 흘러가 버려요. 오래 남는 정보가 새 사용자를 붙잡고, 같은 질문 문의를 줄여요(운영 부담이 오히려 줄어요).
- **안전·운영**: 낮음~중간. 법·세금 내용은 "참고용, 공식 안내 링크" 표시 필수, 날짜 표시, 1년 지나면 다시 확인 표시.
- **난이도**: 중.

### C. 함께하기 챌린지 (추천 ★★)
- **무엇**: 짧고 가벼운 함께하기. 예: "야간 끝나고 7시간 자기 2주", "이번 달 배달비 줄이기"(가계부 연계), "쉬는 날 걷기". 모임 단위로 참여 수·응원만 보이고 순위·벌칙 없음, 하루 빠져도 끊기지 않음(하트·에너지 금지 규칙과 맞춤).
- **보상**: 끝까지 하면 배지 + 묶음 7일권 하루 더 같은 '보상형' 쪽. 현금·포인트 없음.
- **왜**: 이탈 방지에 직접 효과. 근무표를 아니까 "근무에 맞춘 목표"(야간 주에는 목표 낮춤)가 가능.
- **안전·운영**: 낮음(글이 아닌 체크와 응원 위주). 건강 관련 문구는 의료 조언 아님 표시.
- **난이도**: 중.

### D. 만든 분 생태계 깊게 (추천 ★★)
- **무엇**: ① 만든 분 강좌 글(스튜디오 수식·규칙 쓰는 법, 단골 이상만 쓰기) ② 함께 만들기(원작자 허락 받은 공동 작품, 이름 둘) ③ 만든 분 라운지(단골 이상 공개 방, 요청 모아 보기·서로 피드백) ④ 공모를 월 1회에서 '직종 방 공모'로 넓히기.
- **유료 판매**: 이번에도 안 하기 추천(결제·세금·환불·분쟁 부담). 보상은 프로 기간으로.
- **안전·운영**: 중간(공동 작품 출처 다툼). 출처 줄·계보가 이미 있어 감당 가능.
- **난이도**: 중~대.

### E. 지역·직장 모임 (조건부, 좁게)
- **지역**: 시·도 단위 꼬리표만(정확한 위치·동네 인증은 안 함). 시세처럼 "경기 알바" 같은 거르기 정도.
- **직장**: 회사 정보 광장은 익명 그대로. 그 안에 '같은 조(A조·B조)' 칩 정도. 조 단위는 사람이 적어 신원이 드러날 수 있어 **참여자 5명 넘을 때만** 보이게.
- **안전·운영**: 중간~높음. 사람이 적은 곳일수록 신원 노출·직장 내 다툼 위험.
- **난이도**: 소~중.

### F. 하지 않기 추천 (안전이 먼저)
- **1:1 쪽지·실시간 채팅방**: 괴롭힘·사기·불법 권유가 신고 밖에서 일어나요. 1인 운영으로 감당 못 해요.
- **오프라인 모임·번개**: 사고·범죄 책임 문제.
- **위치 기반 '근처 사람'**: 교대 근무자 출퇴근 시간이 드러나요(근무표 + 위치 = 매우 위험).
- **근무표 공개·교대 교환 매칭**: 1.37 후보에 이미 있음. 교환은 지금처럼 카톡 카드까지.

## 3. 수익·이탈 방지와 연결

- 마을은 계속 광고 없음, 보기·쓰기·참여는 무료(V22 그대로).
- **보상형 쪽**: 챌린지 완주, 공모 당선, 정보 모음에 채택된 답 → 프로 기간·7일권 하루 같은 '확실히 받는 느낌'. 현금성 없음.
- **프로는 '더 하고 싶은 사람'에게**: 챌린지 기록 길게 보기, 정보 모음 내 노트 붙이기, 직종 방 여러 개 팔로우 같은 새 고급 기능만(지금 무료인 것은 잠그지 않음).
- **이탈 방지 효과 순서(추정)**: A 직종 방(내 얘기가 있음) > C 챌린지(돌아올 이유) > B 정보 모음(새 사용자가 남음) > D(창작자 한정).

## 4. 추천 묶음과 1.36에 넣을 때의 부담

- **추천안**: A 직종 방 + B 정보 모음을 먼저, C 챌린지를 그다음, D는 공모 넓히기·강좌 글, E는 시·도 꼬리표와 '같은 조'만, F는 하지 않기 목록에 넣기.
- **시점 기본값: 1.36에 넣기**(사용자 원칙 "1.37로 미루지 않음, 늦어져도 온전히").

| 묶음 | 맡을 갈래(추천) | 늘어나는 시험 |
|---|---|---|
| A 직종 방 | 마을 브랜치(PR #144, 마을 전체 조사 스레드) + 관리자 앱 방 목록은 F 갈래 | 6유형 × 직종 고르기·바꾸기, 빈 방이 유형 광장에 합쳐 보이는지, 검색·차단·단계 제한이 방에서도 그대로인지 |
| B 정보 모음 | 마을 브랜치 + 관리자 앱(F 갈래 문의 정리함의 '자주 묻는 질문'과 한 줄로), 급여 '왜?' 연결은 1.36 코드 스레드 | 도움 됐어요 답 → 관리자 채택 → 정보 한 장 → 급여 화면 '왜?'까지 폰 두 대 + 관리자 앱 한 바퀴 |
| C 챌린지 | 마을 브랜치, 7일권 보상 연결은 수익 코드(1.36 코드 스레드) | 근무표에 맞춘 목표(야간 주), 빠진 날 끊기지 않는지, 완주 보상이 보상 장부에 남는지 |
| D 만든 분 | 프로필 스레드(강좌 글·라운지) + F 갈래(공모 보상) | 단골 단계 권한, 공동 작품 출처 줄·계보, 직종 공모 고르기·보상 |
| E 지역·같은 조 | 마을 브랜치(시세 지역 칸 재사용) | 회사 방 익명 유지, 5명 이하일 때 칩이 숨는지 |

- **부담 요약**: 서버 표 2개(직종 방, 정보 모음)와 챌린지 표 1개, 관리자 앱 화면 2개(방 목록, 정보 모음 편집)가 늘어요. PC 실사용 시험은 6유형마다 직종 방·정보 모음·챌린지 세 흐름이 추가돼 지금 마을 시험(V1~V44)의 절반 정도가 더 늘 것으로 보여요(추정).
- **줄이는 법**: A·B를 먼저 끝내 시험하고 C·D·E를 뒤에 붙이면, 시험이 한 번에 몰리지 않아요.

## 5. 사용자가 정할 것
1. 방향: 추천안 그대로인지, 바꿀지
2. 범위: 1.36에 A~E 전부(기본) / 1.36에 A·B만 / 더 논의
3. F '하지 않기'(쪽지·실시간 채팅·오프라인 모임·근처 사람) 승인 여부
4. 직종 방 첫 목록(관리자 앱에서 언제든 바꿈)
