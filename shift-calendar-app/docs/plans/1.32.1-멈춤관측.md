# 1.32.1 멈춤 관측 (2026-10-29)

## 왜

사용자 지시(2026-10-29): "멈춘 상태를 어플이 인지를 해서 해당 문제를 파악할수 있게끔 관측 기능을 넣어서 사용자가 문의로 보고해주면 해결할수 있게 만들어주자. 매번 멈출때 알람 멈춤이라고 뜨는데 실제로는 다른 원인같아."

- 실제 폰(Z Fold, Android 17)에서 앱을 켠 채 화면을 끄고 잠금을 풀면 화면이 멈춰요. 에뮬레이터에서는 재현되지 않았어요.
- 같은 폰에서 1.32.0 OutOfMemoryError 8번. R8 매핑으로 풀면 `Recomposer.knownCompositionsLocked` ← `CompositionContextImpl.composeInitial`이라 남은 하위 composition이 의심돼요.
- 멈춤 알림이 '알람 점검'을 열고, 서버는 단어가 없고 점검 기록이 붙은 문의를 '알람'으로 나눠서 관리자 앱에 '문제 신고 · 알람'으로 보였어요(`inquiries.js` triage).
- 1.32.0의 Android 종료 기록 메모리가 '0MB'(pss가 0인 휴대폰).

## 기록 읽는 법 (개발자)

문의의 `[앱 멈춤 관찰]` 맨 위:
- `최근 3일: 화면 멈춤 N번 (가장 길게 X초) · 화면 안 그려짐 N번 · 눌러도 그대로 N번 · 멈춘 채 끝남 N번`
- `메모리를 가장 많이 쓴 때: heap=a/b (p%)` — 90% 넘으면 '거의 가득'(OOM 앞).

줄(새것부터): `MM-dd HH:mm:ss 무엇 자세히`.
- `화면 안 그려짐 ms=3200 main=free focus=1` → 메인 스레드는 놀고 있는데 창이 다시 그려지지 않음(잠금 화면·표면 쪽, Activity 창 상태). `main=busy`면 `at=`가 막힌 코드.
- `앱 시작 지난번 끝:최근 앱에서 밀어 닫음` → 사용자가 닫음. 바로 앞 줄이 멈춤이면 '멈춘 채 끝남'.
- `화면 크기 바뀜 w=… h=…` → 접기·펴기. `화면 새로 만듦 restore=1` → Activity가 다시 만들어짐.
