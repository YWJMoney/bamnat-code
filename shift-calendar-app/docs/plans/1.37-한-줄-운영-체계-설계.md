# 1.37 한 줄 운영 체계: 관측 → 문의 → 개발 → 출시 → 효과 확인 (설계 1판)

작성 2026-11-01, '밤낮 생태계 평가와 커뮤니티 확장 조사' 스레드.
사용자 결정(10:57 UTC): "제안 모두 승인. 1인 개발 체계이므로 모든 관측성·관리성·문의 대응·개발 진행·처리 완료가 수직 계열화되어 관리성을 아주 뛰어나게. 1.37에 해당 내용 전부와 관리자 앱 부분을 추가해서 진행할 수 있게."

함께 승인된 것: `1.37-남는가와-병목-관측-설계안.md`의 정할 것 3가지(남는가+병목 둘 다, 한 달 1번 '어려웠나요?' 한 줄 물음·끌 수 있음, '찾았는데 없음'은 기능 목록과 맞는 말만 기능 id로).
코드는 고치지 않았어요. 1.36 F 갈래(PR #148, 관리자 할 일함·묶기·이어 붙이기·문의 답 바로 알림) 위에 쌓는 설계예요.

---

## 1. 목표

**개발자 한 명이 하루 15~30분 관리자 앱을 열어, 무엇이 문제이고 무엇을 고쳐야 하며 고친 것이 효과가 있었는지를 한 줄로 따라가요.** 신호가 들어와서 사용자에게 결과가 돌아가기까지 어느 칸에서도 끊기지 않고, 빠진 일이 없게 해요.

```
 관측            모으기·판단          개발              출시               돌려주기·확인
 ─────────────── ─────────────────── ───────────────── ────────────────── ──────────────────
 남는가·병목      할 일함 하나          개발 꾸러미        판 묶기             문의한 분께 알림
 멈춤·느림·실패   같은 것 묶기          (Claude 스레드)   출시 노트 초안        출시 뒤 지표 전·후
 문의·신고·요구   우선순위 점수         PR·빌드·PC 확인    기능 스위치·공지      나빠지면 다시 열기
 '어려웠나요?'    기한·경보             상태 자동 갱신                          닫기(이유 기록)
```

하나의 '일'(카드)이 이 줄 전체를 지나가요. 카드에는 처음 신호부터 마지막 확인까지 기록이 붙어 있어요.

---

## 2. 단계별 설계

### 2-1. 관측 (들어오는 모든 신호)
| 신호 | 출처 | 1.37에서 할 것 |
|---|---|---|
| 남는가(설치 주차별 D1·D7·D30, 첫 주 행동별, 기능별 7일 재사용) | 사용 통계 확장 | 관측 설계안 3장 |
| 병목(흐름 단계 빠짐, 헛누름, 왔다 갔다, 그냥 닫음, 찾았는데 없음, 느림, 실패) | 사용 통계 확장 | 관측 설계안 4장 |
| 멈춤·비정상 종료 | 멈춤 관측(STAB-10~14), 지금은 문의에 붙을 때만 | 동의한 분은 **횟수·화면·구간만** 날마다 묶음으로(내용 없이), 판별 비교 |
| 성능·크기 | 시작 시간·조회 시간(이미), 앱 크기 예산 | 화면 그리기 시간 추가, 판마다 예산 표 |
| 문의·스튜디오 요구·신고·사진 검사 | 1.36 할 일함 | 그대로 받음 |
| '어려웠나요?' 한 줄 | 새로(한 달 1번, 끌 수 있음) | 어려움이면 화면 이름과 함께 할 일함으로, 원하면 문의로 이어 쓰기 |
| 리뷰(Play) | 사용자가 Play Console에서 | 관리자 앱에 붙여 넣으면 같은 할 일로(자동 수집은 안 함) |

### 2-2. 모으기·판단 (할 일함 하나, 1.36 F를 넓힘)
- **자동 카드 만들기**: 관측 신호가 기준을 넘으면 카드가 저절로 생겨요. 예: "급여 설정 3단계에서 빠짐 42%(지난 판 30%)", "스튜디오 '올리기' 그냥 닫음 60%", "1.37.0에서 달력 화면 멈춤 하루 12대".
- **같은 것 묶기**: 같은 화면·같은 흐름의 문의, 병목 신호, 멈춤, '어려웠나요?'를 한 카드로 묶어요. 카드에 "문의 5 · 병목 1 · 멈춤 3대"처럼 근거 수가 쌓여요.
- **우선순위 점수**: 영향(몇 대·몇 %) × 심각도(데이터 손실·알람 > 돈 계산 > 사용성 > 꾸밈) × 추세(늘고 있나). 점수 순으로 줄 세우고, 개발자가 손으로 바꿀 수 있어요.
- **분류**: 새 문제 · 같은 것 · 이미 고침(어느 판) · 개발 중 · 자주 묻는 질문 · 하지 않음(이유). 1.36 문의 정리함 분류를 모든 카드에.
- **기한과 경보**: 종류별 기한(안전·법 신고 24시간, 임시조치 요청 법정 기한, 문의 3일, 개선 후보 다음 판 계획 때). 기한 넘음·급변(멈춤 급증, D7 하락)은 첫 화면 빨간 줄 + 개발자 휴대폰 알림(문의 답 바로 알림과 같은 길).

### 2-3. 개발 (Claude 스레드와 잇기)
- **개발 꾸러미**: 카드에서 '개발로 보내기'를 누르면, 근거(묶인 문의 원문 요약·지표 그래프 값·재현 순서·관련 화면·기능 id)를 한 덩어리 글로 만들어요. 지금 `GET /api/admin/inquiries/handoff`를 넓혀 모든 카드에. 개발자는 이걸 프로젝트 채팅에 붙이면 Claude 스레드가 바로 시작해요.
- **상태 되돌려 받기**: Claude 스레드가 작업하며 짧은 명령으로 카드 상태를 올려요(지금 `d<id> 완료 1.36.0` 형식을 넓힘): `개발 중(브랜치·PR)` → `코드 고침, 확인 전(빌드)` → `에뮬레이터 확인됨` → `출시 대기(판)`. CLAUDE.md 3-1의 "확인된 것만 고쳤다"가 상태로 강제돼요(확인 전에는 '고침'으로 못 넘어감).
- **GitHub를 관리자 서버가 직접 부르지 않아요.** 비밀 토큰을 서버에 두지 않기 위해, 상태는 Claude 스레드가 관리자 API로 올리는 방식(관리자 토큰·권한은 지금 규칙 그대로).

### 2-4. 출시
- **판 묶기**: '출시 대기' 카드를 판(예: 1.37.1)으로 묶으면 출시 노트 초안(사용자 말로)과 `사용자가-해야-할-일` 초안이 저절로 만들어져요.
- **기능 스위치·공지와 잇기**: 문제가 큰 카드에서 바로 그 기능 스위치(FLAG) 끄기나 공지 올리기를 할 수 있고, 카드 기록에 남아요(되돌리기 있음).

### 2-5. 돌려주기·효과 확인·닫기
- **문의한 분께**: 판이 나가면 묶인 문의 모두에 "1.37.1에서 고쳤어요" 답이 한 번에 가요(문의 답 바로 알림 PUSH-01).
- **전·후 비교**: 출시 7일·14일 뒤, 그 카드를 만든 지표(빠짐 %, 멈춤 대수, '어려웠나요?' 비율)를 지난 판과 자동 비교해 카드에 붙여요. 나아졌으면 '효과 확인됨'으로 닫기 제안, 나빠졌거나 그대로면 다시 열려요.
- **닫기 이유**: 닫을 때 이유를 꼭 골라요(고침·효과 확인 / 같은 것 / 하지 않음 / 사용자 답 없음). 닫힌 것도 같은 신호가 다시 오면 되살아나요.

## 3. 관리자 앱 화면 (데스크톱·휴대폰 폭)

1. **오늘** (첫 화면): 빨간 줄(기한 넘음·급변), 오늘 남은 일 N, 이번 주 D7 한 숫자, 판별 멈춤 대수, '하루 15분' 처리 순서 목록.
2. **할 일함**: 1.36 그대로 + 자동 카드·근거 수·점수·상태 줄. 키보드(j/k/e/r), 휴대폰 한 손 넘기기.
3. **남는가·병목**: 관측 설계안 5장 화면.
4. **판**: 판마다 담긴 카드, 출시 노트 초안, 출시 뒤 전·후 비교 표, 크기·성능 예산.
5. **운영 기록**: 누가·언제·무엇을(제한·가림·스위치·공지·답), 되돌리기.
6. **주간 보고**: 월요일마다 한 장(새로 들어온 일, 닫은 일, 효과 확인된 고침, 나빠진 지표, 다음 주 추천 3가지). 프로젝트 파일 `계획/`에 옮겨 둘 수 있게 내보내기.
7. **안전·법 대기열**: 불법촬영물·명예훼손 임시조치·청소년 관련 신고는 따로 맨 위, 법정 기한 표시(1.37 '규모 대비 안전'과 같은 줄).

## 4. 지킬 선
- 관측은 관측 설계안 2장 원칙 그대로(사람 잇지 않음, 내용 없음, 20대 미만 숨김, 끌 수 있음, 처리방침 새 판).
- 관리자 서버에 GitHub·Play 비밀값을 두지 않아요. 출시와 합치기는 사용자가 해요(CLAUDE.md 7항).
- 자동으로 만드는 것은 '카드·초안'까지예요. 답 보내기·스위치 끄기·제한은 개발자가 눌러야 해요.
- 실제 서버가 아니라 로컬 서버로 한 바퀴를 먼저 확인해요(CLAUDE.md 3-1).

## 5. 1.37 안에서의 순서 (제안)
1. 관측 바탕: 사용 통계 확장(남는가·병목·멈춤 횟수), 처리방침 새 판 초안
2. 할 일함 넓히기: 자동 카드·묶기·점수·기한·경보
3. 개발 잇기: 개발 꾸러미, 상태 명령 넓히기
4. 출시·돌려주기: 판 묶기, 출시 노트 초안, 묶음 답, 전·후 비교
5. 화면: 오늘·남는가·병목·판·주간 보고·안전 대기열
6. 한 바퀴 시험: PC 에뮬레이터 두 대 + 로컬 서버로 "앱에서 막힘 → 카드 생성 → 개발 꾸러미 → 고친 빌드 → 출시 묶기 → 답 알림 → 전·후 비교"까지
- 이 체계를 1.37의 다른 일(생태계 확장, 가계부 혁신, 길잡이)보다 **먼저** 세우기를 추천해요. 그래야 다른 일의 효과를 이 줄로 재요.
