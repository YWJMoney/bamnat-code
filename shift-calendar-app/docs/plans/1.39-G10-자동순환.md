## 3. 전달 길과 업데이트 횟수

잦은 앱 업데이트를 줄이려고 개발사항마다 `route`를 적어요: `server`(서버 배포) · `remote`(원격 자료) · `flag`(기능 스위치) ·
`app`(2주 정기) · `hotfix`(긴급). 긴급 기준은 진보안 7장 그대로(알람이 안 울림, 데이터가 사라짐, 앱이 안 켜짐, 돈 계산이 크게 틀림,
개인정보 노출, 결제 잘못) + 4장 제안. Play 인앱 업데이트는 서버 `/api/config` `update {urgentMin, flexibleMin}`로:
`urgentMin`보다 낮은 판은 Play 전체 화면 업데이트, `flexibleMin`보다 낮은 판은 뒤에서 받고 '다시 시작'을 물어요(판마다 한 번). 0이면 묻지 않아요.

## 4. 수면 문제와 긴급 (사용자 '고민해봐' → 제안 → **사용자 승인 2026-11-07 23:14**)

**결정: 수면 중 아래 넷만 긴급(hotfix)으로, 나머지는 2주 정기.**

| 긴급으로 | 왜 | 먼저 할 일(앱 업데이트 전) |
|---|---|---|
| 깨우는 알람(수면 측정 중 알람)이 안 울리거나 늦게 울림 | 알람과 같아요(지각·결근) | 이미 알람 긴급 기준에 들어 있음 |
| 아침에 측정이 멈추지 않아 마이크·녹음이 계속됨 | 개인정보 약속(소리 클립은 폰에만 7일)과 배터리 | 관리자 앱 기능 스위치 `sleep.sound` 끄기(바로 닿음) → 고친 앱은 긴급 |
| 방해 금지 모드를 켠 채 풀어 주지 않음 | 전화·다른 알림을 놓침 | 스위치 `sleep.auto` 끄기 → 고친 앱은 긴급 |
| 소리 클립이 7일 넘게 남거나 지워지지 않음 | 처리방침에 쓴 약속을 어김 | 같음 |

긴급이 아닌 것: 계획 대비 잔 시간·아침 기분 계산 차이, 그래프·문구, 소리 분류 정확도, 하룻밤 측정이 빠짐(기록은 남음).
수면 기록이 사라지는 것은 이미 '데이터가 사라짐'으로 긴급이에요. 서버 영향도 점수(`devQueue`)는 위 셋(녹음·방해 금지·클립)을
말하는 문의를 급함으로 세요(점수 순서만 바뀜, 출시를 정하지 않음).

## 5. 지킬 선

- 문의 원문·사진·폰 정보·연락처는 저장소·GitHub·Action 로그에 들어가지 않아요. `tools/dev_status.py check`가 메일·전화번호·문의 번호를 막아요.
- 요금(`tier`)은 저장소에 적지 못해요(검사가 막음). 서버도 최고 관리자 세션으로만 정해요(열쇠로는 못 함). 정하기 전 새 기능은 스위치로 잠겨요.
- 서버는 Play에서 **읽기만**(편집을 열어 트랙을 읽고 지움, 확정하지 않음). 출시·멈춤은 사용자가 Play Console에서 해요.
- GitHub Secrets·Variables, Play 서비스 계정 권한, 서버 배포는 사용자 할 일이에요.
