# 1.37 '남는가'와 '병목' 관측 설계안 (논의용 1판)

작성 2026-11-01, '밤낮 생태계 평가와 커뮤니티 확장 조사' 스레드. 사용자 요청(10:51 UTC): "남는가를 보는 데이터를 관리할 수 있게 해야지. 그리고 사용자들이 어디에서 병목을 느끼는지 데이터로 관측할 방법 없을까? 앱 개선 데이터로."
코드는 고치지 않았어요. 근거는 1.36 마을 브랜치(`claude/project-thread-97yrcx`)의 서버 `usage.js`와 앱 `AppContainer.kt`예요.

## 1. 지금 있는 것 (코드 확인)

- **사용 통계 보내기**(첫 실행에서 사용자가 체크, 처리방침상 개인정보로 다룸): 날마다 이벤트 약 25가지를 '그날 한 휴대폰 수·횟수'로만 보내요(`usage.js` `EVENTS`: 앱 열기, 급여 화면, 프로 화면, 공유, 광장 글, 문의, 백업, 알람 울림, 테마 무료 이유 등). 400일 보관, 휴대폰을 잇는 번호는 없어요.
- **더 보내기**(`stats.more`): 시작 시간(구간으로 반올림), 켜진 기능 스위치. `stats.lookup`: 찾기·회사·광장 기다린 시간(처리방침 3.5).
- **멈춤 관측**(STAB-10~14): 멈춤·안 그려짐·'세 번 눌러도 안 그려짐'을 휴대폰에 적고, **문의를 보낼 때만** 붙어요.
- **빈 곳**:
  1. 휴대폰을 날짜끼리 잇지 않는 설계라 **"설치한 분 중 7일 뒤 몇 %가 남았나"를 지금 숫자로는 못 내요.**
  2. 이벤트가 1.33 무렵 것 위주예요. 마을·장터·스튜디오·가계부·7일권 이벤트가 거의 없어요.
  3. "어디서 막혔나"(단계에서 빠짐, 같은 곳 여러 번 누름, 열었다 그냥 닫음, 찾았는데 없음)는 재지 않아요.
  4. 근무 유형별로 나눠 볼 수 없어요(확인 필요: 유형을 보내는 칸을 찾지 못함).

## 2. 원칙 (지금 설계를 지키며 넓혀요)

- **사람을 따라가지 않아요.** 휴대폰 번호·광고 ID·설치 ID를 보내지 않아요. 휴대폰이 **스스로 계산한 결과**(예: "설치 3주차, 오늘 열었음")만 묶음 숫자로 보내요.
- **내용은 절대 안 보내요.** 글, 금액, 근무표, 검색한 말, 회사 이름은 없음. 화면 이름과 단계 번호, 횟수 구간만.
- **적으면 숨겨요.** 한 칸에 휴대폰이 20대 미만이면 관리자 앱에 숫자를 보이지 않아요.
- **사용자가 끌 수 있어요.** 지금 '사용 통계 보내기' 아래 한 줄로. 처리방침 새 판(항목 추가)과 시행일 예고가 필요해요.

## 3. '남는가' 재기 (사람을 잇지 않고)

- **휴대폰이 아는 것**: 설치한 주(예: 2026-W46), 설치 뒤 며칠째인지, 근무 유형.
- **보내는 것**: 날마다 묶음에 `설치 주차 + 경과 구간(0일·1일·3일·7일·14일·30일·60일·90일) + 유형` 한 줄. 서버는 "W46에 설치해 7일째에 연 휴대폰 수"를 더하기만 해요.
- **유지율** = 그 칸의 수 ÷ 같은 설치 주차의 0일째 수. 관리자 앱에 설치 주차별 곡선(D1·D7·D30)과 유형별 비교.
- **첫 주에 무엇을 한 분이 남나**: 휴대폰이 7일째·30일째에 "첫 주에 한 일" 표시 몇 개(알람 켬, 근무 넣음, 급여 설정, 마을 열람, 스튜디오 입힘, 공유 링크 만듦)를 함께 보내요. 서버는 "알람을 켠 분의 D30 = 62%, 안 켠 분 = 31%"처럼 묶어서만 셈. → 1.37 '첫 일주일 길잡이(가)'의 순서를 이 숫자로 정해요.
- **기능별 '7일 뒤에도 쓰나'**: 기능을 처음 쓴 날로부터 7일 뒤 또 썼는지를 휴대폰이 세서 기능 이름 + 예/아니오만 보내요. 장터의 '오래 써요%'(V18)를 앱 전체로 넓힌 것.

## 4. '병목' 재기 (어디서 막히나)

| 신호 | 휴대폰이 세는 것 | 무엇을 알 수 있나 |
|---|---|---|
| **단계 흐름(퍼널)** | 정해 둔 흐름마다 어디까지 갔는지 단계 번호. 예: 첫 설정(유형→추천 켜기→근무 넣기→알람), 급여 설정(시급→수당→세금→결과), 장터(카드→입어 보기→입기), 스튜디오(열기→고치기→입히기→올리기), 문의(열기→쓰기→보내기), 7일권(제안 보기→광고→열림) | 몇 % 가 몇 번째 단계에서 빠지는지 |
| **헛누름** | 같은 자리를 2초 안에 3번 이상 누름(이미 멈춤 관측에 '세 번 눌러도'가 있어 재사용), 화면 이름만 | 단추처럼 보이는데 안 되는 곳, 느린 곳 |
| **왔다 갔다** | 같은 두 화면을 1분 안에 3번 넘게 오감 | 길을 못 찾는 곳 |
| **열었다 그냥 닫음** | 편집 창·시트를 열고 저장 없이 닫음, 화면 이름별 비율 | 어렵거나 무서운 창 |
| **찾았는데 없음** | 설정·마을 검색에서 결과 0개 횟수(검색어는 안 보냄). 원하면 앱 기능 목록(`FeatureRegistry`)에 있는 말과 맞은 경우만 그 기능 id | 사람들이 찾는데 못 찾는 기능 |
| **느림** | 화면이 그려지기까지 걸린 시간 구간(시작 시간과 같은 방식) | 무거운 화면 |
| **실패** | 서버 오류, 사진 인식 실패, 급여 '확인 필요', 광고 실패, 화면별 횟수 | 고장·약한 곳 |
| **한 줄 물음(가끔)** | 흐름을 끝내거나 그만둔 직후, 한 사람에게 한 달 1번까지 "어려웠던 곳이 있었나요? 쉬움·보통·어려움" + 원하면 문의로 이어 쓰기 | 숫자가 왜 그런지 |

## 5. 관리자 앱에서 '관리할 수 있게'

- **새 화면 '남는가·병목'** (데스크톱·휴대폰 폭):
  - 위: 설치 주차별 D1·D7·D30, 유형별, 버전별(새 판 뒤 나아졌나)
  - 가운데: 흐름별 단계 그래프, 가장 많이 빠지는 단계 상위 10
  - 아래: 화면별 헛누름·왔다 갔다·그냥 닫음·느림·실패 상위 10, 지난 판과 비교 화살표
- **관리할 것**: 볼 흐름·기간·유형·버전 거르기, 흐름 정의(단계 이름) 보기, 20대 미만 숨김 기준, 보관 기간(지금 400일), CSV 내보내기, 측정 스위치(서버에서 항목별로 끄기, 지금 `USAGE_STATS` 쉬기와 같은 틀).
- **자가 발전 고리와 잇기**: 병목 상위 항목이 관리자 할 일함에 '개선 후보'로 들어가고, 고친 판이 나간 뒤 같은 칸 숫자가 나아졌는지 자동으로 붙어요. 문의 정리함에서 같은 화면 문의가 많으면 같이 보여 줘요.

## 6. 해야 할 것과 위험

- 처리방침 새 판(사용 통계 항목: 설치 주차·경과 구간·유형·흐름 단계·화면별 횟수), 시행 7·30일 예고 규칙(D111).
- 이미 '사용 통계 보내기'에 동의한 분께 새 항목을 보낼 때는 한 번 알리고 끌 수 있게.
- 사용자가 적을 때는 숫자가 많이 숨겨져서 처음 몇 주는 판단이 어려워요. PC 에뮬레이터 시험과 문의 정리함을 함께 봐요.
- 앱 크기·배터리: 하루 한 묶음(지금과 같음), 묶음 크기 한도 8KB 안에서.
