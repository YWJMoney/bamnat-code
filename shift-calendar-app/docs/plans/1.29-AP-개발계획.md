# 1.29 묶음 AP: 급여 흐름과 급여 설정의 회사 검색

사용자 요청(2026-10-27): "급여 입력할 때 회사 검색이 안 된다", "급여 설정에 검색 칸이 없다", "안 뜨는 게 아니라 늦게 떠서 안 뜨는 것처럼 보인다". 요구 번호 PAYF-01~PAYF-08.

## 1. 원인 (찾은 것)

1. 1.27의 '우리 회사 급여 방식 찾기'는 검색 칸이 아니라 버튼이었고, 간편 설정 FORM 단계 제목 아래, 명세서 버튼과 형태 카드 6개 사이에 묻혀 있었어요.
2. 급여 설정이 이미 있으면(결과 화면), 본 달력이 아니면, 마법사·회사 급여 화면에서, 서버 주소가 없는 빌드에서는 아예 안 보였어요.
3. 찾기는 서버만 봤어요: 0.3초 쉬고 2.5초 기다린 뒤 빈 목록을 "급여 방식이 없어요"로 보여 줬어요. 늦게 온 답이 "없음"으로 보였어요.
4. 이 급여 방식 쓰기가 서버에 '쓰는 사람'으로 세지 않았어요(api.use 없음). 그래서 'n명 쓰고 있어요'가 늘지 않았어요.
5. 회사 급여를 고른 바로 뒤 CompanyPayScreen이 "이 회사 급여 설정을 쓸까요?"를 다시 물었어요.
6. 규칙만 있는 명세서에서 확인 단계까지 가면 기본급 0원이 저장될 수 있었어요(0원·이상한 예상).
7. 첫 설정 끝의 급여 질문 시트가 '이 정보를 다른 사람이 사용해도 될까요?' 대화상자와 겹칠 수 있었어요.
8. 서버 검색의 lead.pay는 본 부서 대표 주기만 봐서, 다른 사업장에 급여 방식이 있어도 "없음"이었어요.

## 3. 정한 것

- 쓰고 있는 급여 방식 기록은 AS가 맡은 CompanyStore를 건드리지 않으려고 따로 `PayWayStore`(prefs `pay_way`)에 둠. `SettingsFilesBackup.PARTS`에 넣어 백업·복원됨. DB(Room 21)는 그대로.
- 기본급은 따로 화면을 더 만들지 않고 회사 방식을 넣은 같은 화면 아래에서 확인(한 번 더 누르는 일 없음).
- 맞아요·달라요는 기존 VoteButtons(문구 '맞았어요')를 그대로 씀. 급여 방식으로 쓰는 설정은 설정 화면의 투표 카드에서 빼서 두 번 묻지 않음.
- 검색 결과 기억은 메모리에만(앱 실행 동안 5분). 서버 클라이언트의 속도(CompanyClient·서버)는 AS 몫이라 공개 함수만 씀.
- 화면 시험에서 '느려요'를 찍으려고 `payGiveUpMs`(시험용 var, 기본 15초)를 둠.

## 3-1. 덧붙인 일(통합 뒤 요청)

- 질문형 설정(PayWizard, 자세히 고치기)의 급여 단계 맨 위도 버튼이 아니라 간편 설정과 같은 바로 치는 검색 칸(PayFindFlow 재사용). 칸 아래에 '없으면 직접 만들어요'와 급여 형태 질문. 찾기 안쪽 단계(쓸까요?·없어요·기본급)에서는 아래 '이전'이 검색으로 돌아가고 '다음'은 숨김.
- 결과 화면의 '처음부터 설정'은 늘 간편 설정부터 열리고(자세히 고치기 상태를 지움), 이미 급여가 있으면 공개 주기에서 온 경우라도 회사 찾기 칸이 첫 질문.
- 시험: APScreenshotTest 1242(설정 고치기 → 검색 칸), 1243(질문형 검색 칸·결과), 1244(질문형에서 쓰기 → 기본급 → 저장), 1245(작은 화면 200%).
