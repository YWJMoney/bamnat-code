# 1.29 AQ 개발계획: 사진 읽기 정확도, 회사 규칙 사진, 칸 직접 넣기, '사진이 달라요'

추적표: PHOTO-01 ~ PHOTO-12. 결론부터 말하면, 사용자가 보낸 화학 공장 명세서와 계산 방법 두 장을 이제 전부 읽어요.
명세서 960/960, 시간 160/160이고 계산 방법은 10줄 200/200이에요. 1.28은 명세서 60.2%를 읽었고 계산 방법에서는 규칙을 하나도 읽지 못했어요.

## 2. 정한 것

- 사진 파일은 저장소에 넣지 않았어요. 실제 두 장은 이름과 IP를 지우고 글자 상자 자료(PlantSample.kt)로만 옮겼어요. OOO, OO화학, 남부공장, XX Chem 10.11.222.33처럼 바꿨어요.
- 사진은 폰 안에서만 읽어요(D68). 서버로 가는 것은 '사진이 달라요' 횟수뿐이고 사진·글자·금액은 가지 않아요.
- photo.wrong 깃발은 LEGAL이고 기본으로 꺼져 있어요. 처리방침 3.3 개정과 함께 켜요. 꺼져 있을 때는 누른 횟수를 폰에 모아만 둬요.
- 통상시급은 명세서의 가산 줄(시간·배율·금액)로 찾아요. 소수 자리가 가장 적은 값을 고르고, 원 자르는 법은 올림, 반올림, 내림 중 맞는 것을 써요. 결과 칸은 체크된 채로 보여 줘서 사용자가 빼거나 지울 수 있어요.
- 1.28처럼 글자만 있는 읽기(시험용 가짜)는 그대로 두고, 글자 상자가 있을 때만 표 읽기를 써요.
- DB는 바꾸지 않았어요(Room 21 그대로). 통상시급은 PayStore JSON에 있을 때만 써요.

## 4. 남은 것

- ML Kit은 JVM에서 돌지 않아요. 그래서 실제 두 장의 시험 자료는 사진을 보고 옮긴 글자 상자예요. 실제 폰에서 두 장을 다시 찍어 확인해 주세요.
- WonRounding에 내림(DOWN)이 따로 없어서 '마지막에 자름(AT_END)'으로 넣어요.
- 처음 설정의 근무표 사진 화면(AP 몫)에는 '사진이 달라요'를 달지 않았어요.
- 화면 사진 1258~1269는 쓰지 않았어요.

## 5. 고친 오류 (깊이 본 결과)

명세서
1. 직급수당 같은 이름이 머리글로 빠졌어요.
2. 봉급과 기여금의 역할이 틀렸어요.
3. 적힌 지급합계가 항목 합보다 작아도 '맞음'으로 봤어요(adds/consistent 대체 값).
4. 교대근무수당을 대근(연장)으로 읽었어요.
5. 야간근무수당을 그냥 수당으로 읽었어요.
6. 이름 오른쪽 반 줄 아래에 선 금액을 잃었어요.
7. 워터마크 숫자가 금액 칸에 섞였어요.
8. 각도가 없는 화면 사진에서 기울기를 잘못 짐작했어요(금액 칸의 계단을 기울기로 봤어요).
9. 다르게 만든 사진(흑백·두 배)에서 읽은 글자 상자를 원래 사진 자리로 되돌리지 않았어요.
10. 흑백 변형이 모니터 사진의 모아레를 점으로 찍었어요.

규칙
11. 휴일 8시간 이내/초과 두 단계를 우리 회사 규칙 하나로 읽었어요.
12. 가산에 붙은 야간 시간대를 버렸어요.
13. 여러 대상 가산(연장·야간·휴일)에서 야간만 설정했어요.
14. 상여 '각 100%'를 해마다로 읽었어요.
15. 휴게 '포함하지 아니한다'를 읽지 못했어요.
16. 야간수당 시간당을 월 금액으로 읽었어요.
17. 해마다 주는 수당을 달마다로 읽었어요.
18. 꺾인 조문 줄을 읽지 못했어요.
19. 조문 머리가 다른 가산 이름을 댔어요.
20. 달 목록의 쉼표가 상여를 쪼갰어요.
21. 근속 구간을 읽지 못했어요.
22. 평일연장을 요일 규칙으로 읽었어요.
23. 세금 가족에서 배우자를 자녀로 셌어요.

## 6. 개인정보

- 보내는 것: 날짜, 화면 종류(코드), 앱 판, 이유 코드, 횟수. 사진, 글자, 금액, 이름, 기기 번호는 보내지 않아요.
- 서버는 코드와 숫자만 받고 나머지는 거절해요. 같은 묶음은 한 번만 받고, 네트워크마다 하루 30번까지 받아요. 400일 뒤 지워요. 표 photo_wrong은 서버가 스스로 만들어요.
- 처리방침 3.3에 한 줄이 필요해요: "사진 읽기가 틀렸다고 누른 횟수(날짜·화면·앱 판·이유)를 모아 사진 읽기를 고치는 데 써요." 개정 전까지 photo.wrong은 꺼져 있어요.

## 7. 사용자가 할 일

1. 처리방침 3.3에 위 한 줄을 넣고 개정일을 정해 주세요. 그 날짜로 photo.wrong을 켜요.
2. 회사 서버를 다시 배포해 주세요(/api/photo-wrong).
3. 실제 폰에서 화학 공장 명세서와 계산 방법을 다시 찍어 확인해 주세요. 틀린 곳이 있으면 '사진이 달라요'를 누르거나 문의로 알려 주세요.
