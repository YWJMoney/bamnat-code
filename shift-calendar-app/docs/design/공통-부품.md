# 공통 부품과 값 (2.0.0부터, 갈래 P 정본, [RVP-84])

화면을 만들거나 고칠 때 **이 문서의 부품과 값만** 써요. 통과 기준은 `docs/디자인-품질-조건.md`(조건 16가지, 저장소 맨 위 `CLAUDE.md` 8항)이고, 이 문서는 그 조건을 코드로 지키는 법이에요. 세는 시험(10절)이 CI에서 지켜요.

- 맡은 곳: 갈래 P(추적 번호 `RVP-`). 부품을 고치거나 새로 만들 일이 있으면 직접 만들지 말고 갈래 P에 보내 주세요(통합 스레드 경유).
- 새 모양을 만들지 않아요. 카드·단추·떠 있는 단추·탭·빈 화면·기다림·인터넷 없음 모양은 아래 부품으로만.
- 부품이 아직 없어서 조건을 못 지키면 PR 품질 표에 '갈래 P 부품 대기'라고 적고, 부품이 나오면 그 갈래가 다시 고쳐요.

## 2. 공통 값

### 모서리 (설정 › 모서리 '둥글게·기본·각지게'를 따라요)

| 토큰 | 기본 | 쓰는 곳 |
|---|---|---|
| `MaterialTheme.shapes.extraSmall` | 6dp | 작은 표시, 글자 바탕 |
| `MaterialTheme.shapes.small` | 10dp | 칩, 작은 상자, 칸 |
| `MaterialTheme.shapes.medium` | 14dp | 카드, 안내 카드, 입력 상자 |
| `MaterialTheme.shapes.large` | 20dp | 큰 카드, 시트 안 묶음 |
| `MaterialTheme.shapes.extraLarge` | 28dp | 시트 위쪽, 검색 상자처럼 알약에 가까운 것 |
| `CircleShape`, `RoundedCornerShape(50)` | 원·알약 | 점, 막대(높이의 절반), 동그란 색 칸 |

- 직접 적은 dp는 4dp 이하(선·막대 끝·점)만. 위쪽만 둥글면 `shapes.large.copy(bottomStart = ZeroCornerSize, bottomEnd = ZeroCornerSize)`.
- `@Composable` 밖이라 토큰을 못 쓰는 곳 두 곳과 그림 속 휴대폰 틀은 `DesignRulesTest`의 예외 목록에 까닭과 함께 있어요.

### 여백

- 값: **0 · 2 · 4 · 6 · 8 · 12 · 16 · 20 · 24 · 32**, 그보다 크면 8의 배수(40·48·56·64·72·80·88·96).
- 화면 가장자리·카드 사이·카드 안은 `LocalSpacing.current.page / card / inner`(설정 › 촘촘하게 8·12·12 / 넉넉하게 12·16·16)를 먼저 써요.
- 1·3·5·10·14·18dp 같은 값은 새로 쓰지 않아요. 지금 470곳이 남아 있고 숫자는 줄기만 해요.

### 색

| 뜻 | 쓰는 값 | 쓰지 않는 것 |
|---|---|---|
| 글·바탕 | `MaterialTheme.colorScheme`(onSurface, onSurfaceVariant, surfaceContainerLow…) | `Color(0x…)`, `Color.Gray` |
| 조용한 설명 | `QuietInk`(= onSurfaceVariant) | 주황·빨강 글씨 설명 |
| 좋음·주의·위험 | `Tone.Good/Caution/Danger.color()` (`MaterialTheme.bamnat`) | 화면마다 다른 초록·주황 |
| 달력의 뜻 | `LocalCalendarColors.current`(sunday, saturday, warning, changed, sleep, income…) | 직접 적은 빨강·파랑 |
| 색 위의 글자 | `contentColorOn(바탕)` | 흰 글자 고정 |
| 카드 바탕 | `surfaceContainerLow`(안내 카드와 같은 조용한 면), 글은 onSurface·onSurfaceVariant, 아이콘은 primary | `primaryContainer` 바탕 카드(어두운 모드에서 고른 칩·채운 단추와 같은 진한 파랑이라 카드가 큰 단추로 보여요, 통합 HQ-06) |

- **`primaryContainer`는 고른 것(고른 칩·고른 선택 카드)과 옅은 채움 단추에만.** 카드 바탕으로 쓰면 `DesignRulesTest.cardsStandOnTheQuietGround`가 실패해요.
- **빨강은 위험만**(되돌릴 수 없음, 지난 날짜·미지급). 권한 안내·설정 권유는 `Tone.Caution` 또는 `Tone.Plain`. 한 화면에 빨강이 여러 번이면 못 미침이에요.
- 밤 색 화면(`NightSurface`)은 어두운 달력 색과 어두운 뜻 색을 함께 줘요. 밤 화면에 따로 색을 만들지 않아요.
- 색만으로 뜻을 전하지 않아요: 아이콘이나 글자를 함께(조건 14).

### 글자

- `MaterialTheme.typography`의 이름(titleLarge, bodyMedium, labelSmall…)으로만. 숫자 줄은 `NumberStyle`을 더해요.
- **10sp 아래는 없어요**(autoSize 최솟값도 10sp). 12sp 이하는 보조 정보에만.
- 금액은 글자를 줄이지 말고 줄을 바꾸거나 한 단계 낮은 글자 모양으로(조건 12, PC-11).

### 움직임

| 이름 | 길이 | 쓰는 곳 |
|---|---|---|
| `BamnatMotion.open()` | 260ms | 카드·시트가 열리고 접힘, 쪽 넘김 |
| `BamnatMotion.fill()` | 800ms | 막대·고리가 차오름 |
| `BamnatMotion.count()` | 600ms | 숫자가 올라감 |

`BamnatMotion.spec(…)`으로 쓰면 '움직임 끄기'와 휴대폰의 '애니메이션 삭제'에서 0이 돼요. 끝없이 도는 움직임은 `LocalMotionOff`를 보고 멈춰요. 다른 길이를 새로 만들지 않아요.

## 3. 단추 위계

1. **채운 단추(`Button`)는 화면(창·시트 하나)에 하나**: 지금 할 일 하나. 저장처럼 시간이 걸리면 `SaveButton`.
2. 글자 단추(`TextButton`)는 2개까지: 취소, 나중에.
3. 나머지는 `⋮`(`IconButton` + `DropdownMenu`)나 '더 보기'로 보내요. 같은 무게의 단추를 줄지어 놓지 않아요.
4. 한 줄 더하기는 `AddButton("지출 적기")`, 목록 화면의 큰 더하기는 `AddFab`(아래).
5. 지우기처럼 되돌릴 수 없는 일만 빨강(`ButtonDefaults.buttonColors(containerColor = Tone.Danger.color())`), 그것도 확인 창 안에서만.
6. 안내 카드 안 단추는 채우지 않아요(`NudgeCard`가 글자 단추 하나로 그려요).

`DesignRulesTest.oneFilledButtonPerScreen`이 함수마다 채운 단추를 세요. 이미 둘 이상인 30파일(넘친 수 44)은 줄기만 하고, 새 파일은 하나에서 시작해요.

### 떠 있는 단추 `AddFab`

```kotlin
val fab = rememberFabOpen()
Scaffold(
    modifier = Modifier.nestedScroll(fab.connection),
    floatingActionButton = { AddFab("메모 쓰기", onClick = { … }, open = fab.open) },
) { … LazyColumn(contentPadding = PaddingValues(bottom = FabRoom)) … }
```

- 멈춰 있거나 위로 올릴 때 글자가 보이고, 내리면 아이콘만. 글자 130% 이상이면 처음부터 아이콘만(`bigLetters()`). 화면 읽기는 늘 글자를 읽어요.
- 화면에 하나만. 목록 끝에는 `FabRoom` 여유.

### 탭

`com.bamnat.app.ui.components.Tab`(Material 탭과 같은 모양, import만 바꿔요): 고르지 않은 탭은 회색이라 지금 자리가 한눈에 보여요.

## 4. 누르는 곳

- 48dp(작아도 44dp). `IconButton`은 기본 48dp이니 `Modifier.size(…)`로 줄이지 않아요.
- 작게 보여야 하는 것(색 칸, 점)은 모양은 그대로 두고 `Modifier.minimumInteractiveComponentSize()`를 맨 앞에. 이미 칸마다 48dp 안에 여백이 생기니, 색 칸을 늘어놓은 줄은 사이 간격(`spacedBy`)을 0으로 해요(간격까지 더하면 칸 사이가 벌어져 한 줄에 보이는 색이 더 줄어요).
- 줄 전체를 누르는 것은 `Modifier.heightIn(min = 48.dp).clickable(role = Role.Button) { … }`(화면 읽기가 '단추'라고 말해요).
- 칩의 X는 `ChipClear("날짜 떼기") { … }`(18dp로 보이고 48dp로 눌려요). 칩 안에 X를 넣지 않아요.
- **보이는 닫기가 없는 창은 없어요**: 시트는 `AppSheet`(손잡이 끝 X), 전체 창은 `ToolScreen`(왼쪽 위 X).

## 6. 상태 (조건 7)

| 상태 | 보이는 것 |
|---|---|
| 비었어요 | `EmptyState`: 칸이 + 한 줄 + 단추 하나 |
| 기다려요 | `SkeletonRows`(목록 모양 회색 줄, 화면 읽기 '불러오는 중' 한 번) |
| 인터넷 없음 | `OfflineLine` + 세 문구 중 하나 |
| 저장·실패 | 알림 줄(9절 '되돌리기와 알림 줄 차례')로 말해요 |

인터넷 문구는 세 가지뿐이에요(`NetWords`). 화면이 앞말을 붙일 때는 이 문장으로 끝내요("링크를 못 만들었어요. " + `NetWords.AGAIN`).

| 이름 | 문구 |
|---|---|
| `NetWords.OFFLINE` | 인터넷에 연결되지 않았어요. 연결되면 다시 해 주세요. |
| `NetWords.BUSY` | 인터넷이 없거나 서버가 바빠요. 잠시 뒤 다시 해 주세요. |
| `NetWords.SLOW` | 인터넷이 느려 받지 못했어요. 다시 해 주세요. |

## 7. 말 표 (조건 4·13)

| 쓰지 않는 말 | 쓰는 말 |
|---|---|
| 삭제, 삭제할까요? | 지우기, 지울까요? |
| 수정, 편집 | 고치기 |
| 추가 | 더하기(근무·알람 등은 '○○ 적기'가 더 좋아요) |
| 버튼 | 단추 |
| 아래 탭, 아래 막대 | 아래 메뉴 |
| 최근 수정순 | 최근 고친 순 |
| 실패했습니다, 오류 | 못 했어요 + 다시 하는 법 |

## 9. 뿌리 고침 2·3·4와 '창은 하나씩' 쓰는 법

갈래 P의 두 번째 PR에서 만들었어요(`ui/components/AppSnack.kt`·`Writing.kt`·`AskTurn.kt`, core `guide/OpenAsk.kt`). 새 화면은 아래 이름만 써요.

### 2. 적던 것 지키기 (조건 10)

- 입력 칸의 글은 `remember`가 아니라 `rememberSaveable`(화면이 돌거나 다시 만들어져도 남아요).
- 날이 바뀌거나(자정), 다른 탭에 다녀오거나, 앱이 뒤로 가도 남아야 하는 긴 글(메모·문의·글쓰기)은 `val draft = rememberDraft("memo.new")`: 칸은 `draft.text`를 읽고 쓰고, 저장하면 `draft.done()`으로 비워요. 이 휴대폰에만 7일 남고(`DraftStore`, 백업에 안 들어가요), 열쇠에 날짜를 넣지 않아요. 되살린 글이면 `draft.restored`가 참이라 "적던 글을 이어 써요" 한 줄을 보일 수 있어요.
- 알림·링크로 넘겨받은 값은 한 번 쓰고 비워요(두 번 쓰이지 않게, UIX-48). `NoticeLinks.consume()`이 비우고, 다른 화면에 넘길 값은 `hand`·`takeHanded`로 넘겨요.

### 3. 닫기 전에 묻기 (조건 10)

- 시트: `FormSheet(…, unsaved = 적은 것이 있음)`, 직접 짠 시트는 `GuardedSheet`. 뒤로·쓸어 내리기·X에 한 번 물어요(`DiscardAsk`: "적은 내용을 버릴까요?" 계속 적기 / 버리기). '취소'는 바로 닫아요.
- 입력 칸 있는 창: `DialogProperties(dismissOnClickOutside = false)`.
- 전체 화면: `AskBeforeClose(unsaved) { 나가기 }`는 뒤로 가기에 같은 창을 띄워요. 머리의 X·← 단추는 `val guard = rememberCloseGuard(unsaved) { 나가기 }` 다음 `onClick = guard::close`로 같은 물음을 거쳐요.
- 적고 있는 동안은 `Busy.Writing(unsaved)`(시트·`FormSheet`는 저절로): 그동안 앱이 먼저 여는 창(아래 5)이 끼어들지 않아요.

### 4. 되돌리기와 알림 줄 차례 (조건 10, UIX-44)

- 알림 줄은 앱에 하나(`AppSnack`): `AppSnack.show("메모를 지웠어요", undo = { … })`, 답을 기다려야 하면 `if (AppSnack.ask("…", action = "다시 보기")) …`. 되돌리기 줄 → 실패 → 안내 순서로 줄을 서고(되돌리기끼리는 새것 먼저), 같은 말은 겹치지 않아요. 시간은 화면에 뜬 때부터: 되돌리기·단추 있는 줄 8초, 긴 안내 6초, 짧은 안내 4초(TalkBack 사용자 설정 시간은 더 길게). 1분(되돌리기는 30초) 넘게 기다린 줄과 세 번 밀려난 줄은 버려요.
- 줄을 보이는 곳은 `AppSnackHost()` 하나: 맨 위 화면의 것이 받아요. 아직 `SnackbarHostState`를 넘기는 옛 코드는 `val snackbar = AppSnack.rememberLane()`으로 같은 줄에 서요.
- 되돌리기는 **그 일이 바꾼 것만** 되돌려요(그 사이 바뀐 다른 것은 그대로).
- 토스트(`Toast.makeText`)는 새로 쓰지 않아요(천장 42, 줄기만 해요). 앱 밖 알림이 필요한 곳(위젯·알람·앱을 떠나는 순간)만 예외.

### 5. 열 때 창은 하나씩 (UIX-45·47)

- 앱이 먼저 여는 창(새 처리방침 동의, 체험 동의, 새 소식, 테마 기간 끝남, 업데이트 준비, 테마 새 판, 글자 크기, 출시 감사)은 `if (AskTurn.turn(OpenAsk.WHATS_NEW)) { … }`로 차례를 받아요. 한 번 열 때 하나만, 법이 걸린 것(동의)이 먼저, 적고 있거나 창·시트가 열려 있으면(`Busy.now`) 기다려요. 사용자가 직접 연 것(`asked = true`)은 차례를 기다리지 않아요.
- 새 '먼저 여는 창'은 `OpenAsk`에 줄을 더하고(순서가 곧 차례) 여기에 적어요.

## 13. 알림함에 줄 넣기 (다른 갈래, 검토 HQ-49·50)

사람들과 주고받은 것(내 글·작품에 달린 댓글·좋아요·맞아요·달라요·답)은 **모두 알림함**으로 가요. 달력 위에는 꼭 봐야 하는 것만(5절 `Notice.urgent`). 알림함은 이 폰 안에만 있고 아무것도 서버로 보내지 않아요.

```kotlin
Inbox.post(context, InboxRow(
    key = "market.work:$workId",          // 같은 key는 바꿔 쓰고 맨 위로(묶음: "댓글 3개 · 좋아요 5개", count = 8)
    kind = "market.reaction",             // '다시 보지 않기'가 끄는 단위: 영역.까닭
    section = InboxSection.PEOPLE,        // PEOPLE(사람들 반응) · NOTICE(안내) · SUGGEST(권유, 하나씩)
    title = "내 작품 ‘밤바다’",
    line = "댓글 2개 · 좋아요 5개",
    target = NoticeLinks.Target.MARKET, payload = workId,   // 또는 feature = FeatureRoute(Place.…)
    at = whenItHappened, count = 7,
))
```

- `post`는 사용자가 그 `kind`를 껐거나(다시 보지 않기) 권유를 껐으면(설정 › 기능 켜고 끄기 › 알림함 권유 받기) `false`를 돌려주고 아무것도 넣지 않아요. 넣기 전에 `Inbox.get(context).allowed(kind, section)`으로 물어도 돼요.
- 권유(`SUGGEST`)는 한 번에 하나만 있어요: 새 권유가 앞 권유 자리를 대신해요. 같은 권유를 시스템 알림으로 다시 보내지 않아요.
- 지울 때는 `Inbox.remove(context, key)`. 줄은 30일, 60줄까지 남아요. 끈 종류는 백업에 들어가 새 폰에서도 다시 묻지 않아요.
- 지금 쓰는 `kind`: `market.reaction`, `plaza.reaction`, `invite.friend`, `suggest.companyRule`, `suggest.discover`, 달력 안내는 `calendar.<key>`.
